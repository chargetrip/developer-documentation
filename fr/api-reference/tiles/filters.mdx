Les filtres permettent aux applications d'affiner les stations de recharge renvoyées par l'API du service de tuiles. Au-delà du simple masquage des résultats non correspondants, certains filtres transforment aussi les données des stations afin que la réponse reste pertinente selon le contexte.

## Comment les filtres affectent les données

Lorsqu'une requête inclut des filtres, le service de tuiles effectue deux opérations distinctes :

1. **Exclusion des stations non correspondantes**
   Toute station ne répondant pas aux critères de filtrage spécifiés est entièrement supprimée de la réponse. Cette opération a lieu lorsque des filtres au niveau de la station ou de l'EVSE sont utilisés.
2. **Transformation des données**
   Lorsque certains paramètres de filtrage sont fournis, le service de tuiles recalcule certaines propriétés dynamiques de la station. Cette opération a lieu lorsque des filtres au niveau de l'EVSE sont utilisés.

## Implémentation

Les paramètres de filtre peuvent être ajoutés à l'URL de la requête sous forme de chaînes de requête pour n'importe quel endpoint du service de tuiles (MVT, JSON ou Count). Si aucun filtre n'est appliqué, toutes les stations de recharge disponibles sont renvoyées et aucune transformation de données n'est effectuée.

```bash Tile / Filter / Example
https://api.chargetrip.io/v2/station/..../?{filter_1}&{filter_2}&{filter_n}
```

## Niveaux

Les filtres peuvent exister à deux niveaux : au niveau de l'EVSE ou au niveau de la station, chacun avec son propre impact et ses propres résultats, comme décrit ci-dessous.

### Niveau station

Filtres qui évaluent les attributs globaux de la station. Ces filtres servent uniquement à exclure : ils excluent les stations non correspondantes mais ne modifient jamais les champs de données renvoyés.

`amenities` · `enum` · [Afficher l'URL d'exemple](tip:https://api.chargetrip.io/v2/station?amenities[]=HOTEL)
: Filtre pour inclure uniquement les stations qui proposent les équipements spécifiés.
: `HOTEL`, `SHOPPING`, `BATHROOM`, `SUPERMARKET`, `PLAYGROUND`, `PHARMACY`, `MUSEUM`, `COFFEE`, `RESTAURANT`

`preferred_operators` · `boolean` · [Afficher l'URL d'exemple](tip:https://api.chargetrip.io/v2/station?preferred_operators=true)
: Filtre pour inclure uniquement les stations exploitées par des opérateurs configurés comme préférés. Les opérateurs préférés peuvent être définis dans les paramètres du projet dans le dashboard.
: `true`, `false`

`truck_dedicated` · `boolean` · [Afficher l'URL d'exemple](tip:https://api.chargetrip.io/v2/station?truck_dedicated=true)
: Filtre pour inclure uniquement les stations dédiées ou principalement destinées à la recharge de camions. **Applicable uniquement si la base de données de stations Eco-Movement est utilisée ; sinon, il est ignoré.**
: `true`, `false`

### Niveau EVSE

Filtres qui évaluent les capacités de charge spécifiques de la station. Ces filtres effectuent une exclusion et une [transformation](/api-reference/tiles/filters#exemples-de-transformation-des-données) : les stations non correspondantes sont exclues, et les champs dynamiques des stations correspondantes sont recalculés.

`connectors` · `enum` · [Afficher l'URL d'exemple](tip:https://api.chargetrip.io/v2/station?connectors[]=CHADEMO)
: Filtre pour inclure uniquement les stations dont les EVSE ont les types de connecteurs spécifiés. Accepte un tableau de chaînes avec n'importe quelle valeur de connecteur OCPI 2.2.1.
: `CHADEMO`, `DOMESTIC_A`, `DOMESTIC_B`, `DOMESTIC_C`, `DOMESTIC_D`, `DOMESTIC_E`, `DOMESTIC_F`, `DOMESTIC_G`, `DOMESTIC_H`, `DOMESTIC_I`, `DOMESTIC_J`, `DOMESTIC_K`,
`DOMESTIC_L`, `DOMESTIC_M`, `DOMESTIC_N`, `DOMESTIC_O`, `IEC_60309_2_single_16`, `IEC_60309_2_three_16`, `IEC_60309_2_three_32`, `IEC_60309_2_three_64`, `IEC_62196_T1`,
`IEC_62196_T1_COMBO`, `IEC_62196_T2`, `IEC_62196_T2_COMBO`, `IEC_62196_T3A`, `IEC_62196_T3C`, `PANTOGRAPH_BOTTOM_UP`, `PANTOGRAPH_TOP_DOWN`, `TESLA_R`, `TESLA_S`, `GB_T`,
`CHAOJI`, `NEMA_5_20`, `NEMA_6_30`, `NEMA_6_50`, `NEMA_10_30`, `NEMA_10_50`, `NEMA_14_30`, `NEMA_14_50`

### Exemples de transformation des données

Certaines sorties sont recalculées lorsque des filtres au niveau de l'EVSE sont appliqués. Ces champs sont « transformés » pour ignorer les connecteurs qui ne correspondent pas aux critères de recherche de l'utilisateur.
Ces champs de sortie « dynamiques » sont `connector_maximum_power` et `evse_status_*`.

<details>
  <summary>Même type de filtre, valeurs différentes</summary>
  La requête inclut un filtre de connecteur CHADEMO. La station est incluse car elle possède un connecteur CHADEMO, mais les champs dynamiques sont transformés pour ignorer les chargeurs Combo Type 1.

```bash Exemple d'URL
https://api.chargetrip.io/v2/station?connectors[]=IEC_62196_T1_COMBO&connectors[]=CHADEMO
```

```json Réponse
{
  "id": "station_a",
  // Static: Remains 150 kW (This represents the station maximum power across all connectors)
  "station_maximum_power": 150,
  // Dynamic: Adjusted to 100 kW (Max power of the CHADEMO connector)
  "connector_maximum_power": 100,
  // Dynamic: Counts the 1 CHADEMO chargers
  "evse_status_out_of_order": 0,
  // Dynamic: 0, because the charging Type 1 plugs are filtered out
  "evse_status_available": 1
}
```
</details>
