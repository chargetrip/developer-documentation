GraphQL est un langage de requête pour les API. Il vous permet de demander exactement les données dont vous avez besoin en un seul appel, au lieu de passer par de nombreux endpoints REST fixes.

L'API est construite sur GraphQL. Chaque ressource, comme les véhicules, les stations, les itinéraires et les sessions de navigation, est disponible via une seule API GraphQL. Vous pouvez accéder à chacune sous forme de query, de mutation ou de subscription.

Si vous découvrez GraphQL, la [documentation officielle de GraphQL](https://graphql.org/learn/) est un bon point de départ.

## Endpoints GraphQL

Les queries, mutations et subscriptions sont disponibles aux endpoints ci-dessous. Consultez [envoyer votre première requête](/docs/getting-started/api-request) pour un exemple.

Pour les queries et les mutations, utilisez :

```bash Mutation and Query URL
https://api.chargetrip.io/graphql
```

Pour les subscriptions, utilisez :

```bash Subscriptions URL
wss://api.chargetrip.io/subscription
```

### Authentification

Chaque requête est authentifiée avec les en-têtes `x-client-id` et `x-app-id`. Consultez [autorisation](/docs/getting-started/api-request#en-têtes-dautorisation) pour savoir comment les obtenir et les envoyer.

### Pagination

Les queries de liste utilisent soit les arguments `size` et `page`, soit, pour la pagination par curseur, les arguments `first` et `after`. Consultez [pagination](/api-reference/api/pagination) pour plus de détails.

### Limitation de débit

Les requêtes sont soumises à une [limitation de débit](/api-reference/api/rate-limiting).

### Cycle de vie

Chargetrip utilise une API GraphQL unique et évolutive plutôt que des versions numérotées. Consultez [cycle de vie](/api-reference/api/lifecycle) pour savoir comment nous gérons les changements incompatibles et compatibles.
