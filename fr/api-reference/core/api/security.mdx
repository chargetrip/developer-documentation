---
title: "Sécurité"
description: "Empêchez l'utilisation non autorisée de vos applications en restreignant la plateforme ou l'origine pouvant envoyer des requêtes avec votre identifiant d'application."
---

Les en-têtes envoyés avec une requête, dont `x-app-id`, sont visibles par quiconque inspecte le trafic réseau. Pour empêcher l'utilisation non autorisée de vos applications, appliquez une restriction qui limite la plateforme ou l'origine pouvant l'utiliser.

> [!WARNING] Une seule restriction par application
> Une seule restriction peut être appliquée par application. Pour combiner des restrictions, par exemple un client web et un client mobile, créez une application distincte pour chacun.

## Types de restriction

Quatre types de restriction sont disponibles, chacun adapté à une plateforme ou à un mode de communication différent.

### Web

Restreignez une application web via le référent HTTP, appliqué à l'en-tête `x-app-id`. Plusieurs URL peuvent être ajoutées à une même application.

### Machine à machine (M2M)

Restreignez la communication de serveur à serveur via l'adresse IP (IPv4 et IPv6 sont pris en charge), configurée dans le tableau de bord de l'application. C'est l'option la plus sûre, car les identifiants n'atteignent jamais un navigateur ni un appareil.

### Android

Restreignez une application Android à l'aide des en-têtes `x-app-identifier` et `x-app-fingerprint`, envoyés avec chaque requête.

### iOS

Restreignez une application iOS à l'aide de l'en-tête `x-app-identifier`, qui contient l'identifiant de bundle de l'application.
