title: "Opérations asynchrones"
description: "Découvrez comment fonctionnent les opérations asynchrones de l'API : créez avec une mutation, puis suivez et récupérez le résultat avec une souscription ou une requête."
---

Certaines opérations, comme la création d'un itinéraire ou d'un itinéraire concordant, s'exécutent de manière asynchrone afin de garder l'API réactive. Plutôt que d'attendre qu'une mutation renvoie le résultat complet, vous obtenez immédiatement un `id`, puis vous l'utilisez pour suivre et récupérer le résultat.

## Fonctionnement

1. **Créer**
   Appelez la mutation. Elle renvoie immédiatement un `id`, que vous utilisez à l'étape suivante pour suivre et récupérer le résultat.
2. **Ouvrir une souscription**
   Souscrivez avec l'`id` de l'étape précédente. Pendant le calcul du résultat, la souscription envoie des mises à jour de statut que vous pouvez utiliser pour piloter un état de chargement asynchrone dans votre interface.
3. **Afficher le résultat**
   Une fois que `status` prend une valeur finale, affichez l'interface correspondant à ce résultat.
4. **Récupérer à nouveau un résultat terminé**
   Une fois qu'un résultat a atteint un statut final, il est déjà précalculé. Si vous en avez de nouveau besoin plus tard, par exemple après y être revenu par la navigation, utilisez la requête correspondante au lieu d'ouvrir une nouvelle souscription.

## Où cela s'applique

| --- | --- | --- | --- |

| [Itinéraire concordant](/api-reference/core/matched-route/mutation-create-matched-route) | `createMatchedRoute` | `matchedRoute` | `getMatchedRoute` |
| [Isoline](/api-reference/core/isoline/mutation-create-isoline) | `createIsoline` | `isoline` | `isoline` |
| [Itinéraire camion](/api-reference/core/truck-route/mutation-create-truck-route) | `createTruckRoute` | `truckRoute` | `getTruckRoute` |
| [Navigation](/api-reference/core/navigation/mutation-start-navigation) | `startNavigation` | `navigation` | `navigation` |
