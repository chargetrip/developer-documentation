---
title: Gestion des erreurs
description: "Comprenez comment l'API renvoie les erreurs avec des données partielles, et pourquoi vérifier le corps de la réponse plutôt que le code de statut HTTP."
---

L'API renvoie les erreurs dans le cadre d'une réponse normale, avec les données qui ont pu être résolues. Une requête peut réussir partiellement, donc vérifier uniquement le code de statut HTTP ne suffit pas pour détecter une erreur.

> [!WARNING] Réponses partielles
> L'API renvoie HTTP 200 pour la plupart des requêtes, même lorsqu'elles contiennent des erreurs. Vérifiez toujours la présence d'un tableau `errors` dans le corps de la réponse, plutôt que de vous fier au code de statut HTTP, car `data` et `errors` peuvent être renvoyés ensemble.

## Erreurs

Chaque erreur est renvoyée dans le tableau `errors` de premier niveau, aux côtés de `data`.

`message` · <span class="text-muted">String</span>
: Une description lisible par un humain de l'erreur.

`locations` · <span class="text-muted">Array</span>
: La ligne et la colonne de la requête où l'erreur s'est produite.

`path` · <span class="text-muted">Array</span>
: Le chemin vers le champ à l'origine de l'erreur, par exemple `["vehicleList"]`.

`extensions.exception.code` · <span class="text-muted">String</span>
: Un code d'erreur lisible par une machine. Utilisez ce champ pour gérer les erreurs par programmation, plutôt que de vous baser sur `message`.

`extensions.exception.status` · <span class="text-muted">Integer</span>
: Le code de statut HTTP correspondant à l'erreur, par exemple `403`.

`extensions.exception.message` · <span class="text-muted">String</span>
: Une description lisible par un humain de l'erreur, identique au champ `message` de premier niveau.

`extensions.exception.response` · <span class="text-muted">String</span>
: Le corps de la réponse de l'exception sous-jacente, souvent identique à `message`.

### Localisation

Pour gérer et localiser correctement les messages d'erreur, utilisez `extensions.exception.code` plutôt que `message`. Pour une description de la signification de chaque code, consultez la page de l'opération dans la référence API. `message` ne doit servir que de contexte pour les développeurs, et ne pas être affiché aux utilisateurs finaux.
