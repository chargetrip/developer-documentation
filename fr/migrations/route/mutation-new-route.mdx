# Créer un itinéraire

Migrer avant : T1 2027

Migrez de l'ancien service Route vers la dernière version. Le nouveau service apporte un schéma réorganisé, des préférences d'opérateurs par pays, un calcul d'itinéraire plus rapide et une meilleure maintenabilité.

## Opérations

| Ancien            | Nouveau                                                         |
| ----------------- | ----------------------------------------------------------------|
| `newRoute`        | [`createRoute`](/api-reference/core/route/mutation-create-route)     |

## Modifications générales du schéma

- **Typage explicite** : les champs JSON auparavant flexibles sont désormais explicitement typés dans le schéma pour améliorer la structure et la validation.
- **Conventions de nommage** : les champs utilisent désormais `snake_case` au lieu de `camelCase`.
- **Prise en charge des unités** : les entrées numériques prennent désormais en charge différents types d'unités, exprimées sous la forme d'un objet avec `value`, `type` et un `source` facultatif (`manual`, `telemetry` ou `default`).

## Modifications de la mutation

L'argument `input` de `createRoute` a été réorganisé et simplifié.

### routeRequest

Au niveau racine, les champs suivants ont été supprimés. Les champs liés aux opérateurs sont désormais couverts par les [préférences d'opérateurs](#préférences-dopérateurs), et les champs liés aux commodités ont été déplacés vers leur propre [requête de commodités](/api-reference/core/route/query-get-route-stations-with-amenities) dédiée.

| Champ                  | Déplacé vers                           |
| ---------------------- | -------------------------------------- |
| `operatorIds`          | Supprimé                               |
| `amenities`            | Supprimé                               |
| `amenity_preferences`  | Supprimé                               |
| `operatorRequired`     | Supprimé                               |
| `operatorPrefer`       | Supprimé                               |

### VE

Au niveau du VE, la plupart des champs de premier niveau ont été déplacés dans un objet `vehicle` dédié.

| Champ             | Déplacé vers                          |
| ----------------- | -------------------------------------- |
| `ev.id`           | `vehicle.id`                     |
| `battery`         | `vehicle`                        |
| `climate`         | `vehicle`                        |
| `heat_pump`       | `vehicle`                        |
| `plugs`           | `vehicle.charging.connectors`    |
| `safeRiskMargin`       | `vehicle.charging.risk_margin`   |
| `chargeMode`           | `vehicle.charging.mode`          |
| `bmsConsumption`  | Supprimé                               |

### Charge du véhicule

Les propriétés de charge du véhicule ne sont plus définies à un seul endroit. Elles sont désormais spécifiées pour chaque point `origin` et `via`, ce qui offre un contrôle plus granulaire du poids des occupants et de la cargaison pour chaque tronçon. Elles se trouvent sous `properties.vehicle` pour chaque lieu, et leurs noms de champs changent comme suit :

| Champ       | Déplacé vers          |
| ----------- | --------------------- |
| `occupants` | Inchangé               |
| `cargo`     | `total_cargo_weight`  |

### Télémétrie

Les données de télémétrie suivantes ont été déplacées du niveau racine vers l'objet `vehicle`.

| Champ                 | Déplacé vers     |
| --------------------- | ---------------- |
| `heading`             | `vehicle`  |
| `motor_rpm`           | `vehicle`  |
| `odometer`            | `vehicle`  |
| `outside_temperature` | `vehicle`  |
| `tire_pressure`       | `vehicle`  |
| `vehicle_speed`       | `vehicle`  |

## Changements marquants

Quelques champs de l'argument `input` ont désormais de nouvelles structures plus détaillées. Elles sont décrites plus en détail ci-dessous.

### Préférences d'opérateurs

Les préférences d'opérateurs sont simplifiées en trois niveaux : `high`, `medium` et `low`. Chaque entrée, qu'elle soit classée, exclue ou évitée, peut être limitée à des pays spécifiques via le champ `countries`. Si ce champ est omis, tous les pays sont pris en compte.

```graphql Operator preferences {{ mark: [6,9,12] }}
input: {
  operators: {
    ranking: {
      type: preferred
      levels: {
        high: [
          {
            id: "op1"
            countries: [NL]
          }
        ]
        low: [
          {
            id: "op3"
          }
        ]
      }
    }
  }
}
```

### Poids total des occupants

Un nouveau champ `total_occupant_weight` vous permet de remplacer le poids par défaut des occupants, exprimé avec le nouvel objet d'unité.

```graphql Total occupant weight {{ mark: [6,7,8,9,10] }}
input: {
  origin: {
    properties: {
      vehicle: {
        occupants: 3
        total_occupant_weight: {
          value: 160
          type: kilogram
          source: manual
        }
      }
    }
  }
}
```
