---
title: Itinéraire avec arrêts
description: "Ajoutez des arrêts intermédiaires entre l'origine et la destination avec via, en utilisant des arrêts de lieu ou de recharge pour des trajets réalistes."
---

Lors du calcul d'un itinéraire EV avec l'API Route de Chargetrip, vous pouvez ajouter des arrêts intermédiaires entre l'origine et la destination à l'aide de `via`.

Les arrêts vous permettent de personnaliser le calcul d'itinéraire pour des scénarios de déplacement réels, comme recharger dans une station de recharge préférée, prendre des passagers ou s'arrêter dans un restaurant.


## Types d'arrêts

Chargetrip prend en charge deux types d'arrêts intermédiaires :

| Arrêt | Recharge |  Champ d'entrée | Objectif |
| :--- | :--- | :--- | :--- |
| **Lieu** | Non |  `via.geometry`| Arrêt géographique (prise en charge, livraison, détour touristique, pause café).
| **Station** | Oui | `via.properties.station.station_id`| Station de recharge sélectionnée explicitement.


## Durée d'arrêt

Vous pouvez configurer la durée de chaque arrêt. Selon le type d'arrêt (avec ou sans recharge), le `stop_duration` est configuré à des emplacements différents et se comporte différemment :

### 1. Dans les arrêts sans recharge

La durée d'arrêt est configurée dans `input.via.properties.location.stop_duration`. Cette durée représente la **durée d'arrêt exacte** et s'ajoute directement à la durée totale du trajet sans affecter le temps de recharge ou de conduite du véhicule.

### 2. Dans les arrêts avec recharge

La durée d'arrêt est configurée dans `input.via.properties.station.stop_duration`. Cette valeur représente **la durée d'arrêt minimale**. Le véhicule reste à la station au moins ce temps, mais le planificateur d'itinéraire peut prolonger l'arrêt en fonction du `charge_mode` configuré :

  * `ALWAYS_TO_MAX_CHARGE` : prolonge le temps de recharge si nécessaire pour atteindre le SoC maximal configuré. Si le `stop_duration` demandé dépasse le temps nécessaire pour atteindre le SoC maximal, le temps restant est consigné comme temps d'arrêt inactif.

  * `OPTIMIZE_TRAVEL_TIME` : prolonge le séjour au-delà de `stop_duration` uniquement si cela réduit la durée totale du trajet (par exemple, en supprimant un arrêt de recharge ultérieur). Sinon, recharge pendant la durée exacte demandée. Si le `stop_duration` demandé dépasse le temps nécessaire pour atteindre le SoC maximal, le temps restant est consigné comme temps d'arrêt inactif.

Si aucune valeur n'est fournie, le planificateur optimise la durée de recharge uniquement en fonction du `charge_mode` de l'itinéraire.


## Ajouter une station à un itinéraire existant

Un scénario courant : un utilisateur choisit une station de recharge pour un itinéraire qui comporte déjà des arrêts, par exemple une station alternative affichée dans votre interface. La solution no-code utilise cette approche pour ajouter automatiquement une station comme arrêt `via`, sans logique de réorganisation, afin que l'itinéraire se mette à jour de façon fluide.

L'ordre du tableau `via` correspond à l'ordre dans lequel les arrêts sont parcourus. Une station ajoutée à la fin est visitée en dernier, même si elle se trouve près du début de l'itinéraire. Pour l'insérer à la bonne position, comparez l'emplacement de la station avec les points de passage déjà présents sur l'itinéraire :

1. **Rassemblez les points de passage dans l'ordre.** Prenez `origin`, chaque arrêt `via` existant et `destination` dans le `request_input` de l'itinéraire à modifier. Chaque point de passage du `request_input` dispose de sa `geometry`, y compris les arrêts créés avec une simple `station_id`.

2. **Tracez une ligne passant par les points de passage.** Reliez les points de passage dans l'ordre pour former une ligne. Chaque partie de cette ligne entre deux points de passage est un segment.

3. **Trouvez le segment le plus proche de la station.** Utilisez une bibliothèque géospatiale pour trouver le point de la ligne le plus proche des coordonnées de la station. <a href="https://turfjs.org" target="_blank" rel="noopener noreferrer">turf.js</a> propose par exemple `nearestPointOnLine`, qui renvoie aussi l'index du segment contenant ce point. Cet index est celui du point de passage où commence le segment.

4. **Insérez la station après ce point de passage.** La liste des points de passage commence par `origin` : l'index d'un point de passage dans cette liste correspond donc à la position où insérer un nouvel élément dans `via` pour qu'il se place juste après. Un index de `0` signifie que la station est insérée comme premier arrêt.

5. **N'insérez jamais après la destination.** Lorsque le point le plus proche se trouve sur le dernier segment, l'index peut pointer vers `destination`. L'insérer ainsi placerait la station après la fin de l'itinéraire. Utilisez plutôt le point de passage précédent, afin que la station soit insérée comme dernier arrêt avant `destination`.

### À garder à l'esprit

* La ligne relie les points de passage par des segments droits et ne suit pas les routes de l'itinéraire. Les stations alternatives se trouvent toujours dans un couloir de 5 à 10 km autour de l'itinéraire : elles ne s'en écartent donc jamais beaucoup et le segment le plus proche est généralement exact. Pour les stations situées hors de ce couloir, d'autres solutions peuvent être plus adaptées.
* Le `request_input` de l'itinéraire fait foi. Construisez la nouvelle requête à partir de lui et laissez tous les autres champs, comme `vehicle` et les paramètres `charging`, inchangés.

## Exemples

<details>
  <summary>Calculer un itinéraire avec un arrêt de 30 minutes sans recharge.</summary>
  Sur cet arrêt, un `stop_duration` de 1800 secondes (30 minutes) a été ajouté. Ce sera la durée d'arrêt, puisqu'il ne peut y avoir aucun avantage supplémentaire.

```graphql Example request
mutation CreateRouteWithWaypoint {
  createRoute(
    input: {
      vehicle: {
        id: "60b8d5a2f1c8e9001b9e2831"
        charging: { mode: OPTIMIZE_TRAVEL_TIME }
      }
      origin: {
        type: Point
        coordinates: [4.9041, 52.3676]
      }
      destination: {
        type: Point
        coordinates: [6.9583, 50.9375]
      }
      via: [
        {
          geometry: {
            type: Point
            coordinates: [5.1214, 52.0907] # Utrecht
          }
          properties: {
            location: {
              name: "Utrecht Central"
              stop_duration: 1800 # 30 minutes in seconds
            }
          }
        }
      ]
    }
  ) {
    id
    status
  }
}
```
</details>

  <summary>Calculer un itinéraire avec un arrêt de recharge d'au moins 30 minutes.</summary>
  Sur cet arrêt, un `stop_duration` de 1800 secondes (30 minutes) a été ajouté. Ce sera la durée d'arrêt **minimale**. Si une recharge plus longue est bénéfique pour l'itinéraire, elle sera prolongée.
  
```graphql Example request
mutation CreateRouteWithChargingVia {
  createRoute(
    input: {
      vehicle: {
        id: "60b8d5a2f1c8e9001b9e2831"
        charging: { mode: OPTIMIZE_TRAVEL_TIME }
      }
      origin: {
        type: Point
        coordinates: [4.9041, 52.3676]
      }
      destination: {
        type: Point
        coordinates: [6.9583, 50.9375]
      }
      via: [
        {
          properties: {
            station: {
              station_id: "5e849ea2837bc43df65d19a2"
              stop_duration: 1800
            }
          }
        }
      ]
    }
  ) {
    id
    status
  }
}
```
</details>
