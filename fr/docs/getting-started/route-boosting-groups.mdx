---
title: Prioriser des stations de recharge individuelles
---

Les Boosting Groups vous permettent d'orienter la sélection des stations vers des lieux de recharge spécifiques en fonction de vos propres règles métier.

Alors que les [préférences d'opérateurs](/docs/getting-started/route-operators) permettent de prioriser des réseaux de recharge entiers, les Boosting Groups vous offrent un contrôle granulaire au niveau de la station. Quelle que soit votre raison de favoriser ces stations, comme des tarifs plus bas, une faible utilisation ou un meilleur accord commercial, vous pouvez les placer en haut de la hiérarchie des stations.

## Comment booster des stations

Pour commencer, contactez simplement le [support](https://www.chargetrip.com/contact/support) avec la liste des stations que vous souhaitez prioriser.

Une fois votre groupe configuré et activé sur votre projet, tous les itinéraires calculés avec [createRoute](/api-reference/core/route/mutation-create-route) l'utiliseront automatiquement en arrière-plan, sans aucune modification ni paramètre supplémentaire dans vos requêtes d'API.

## Comment ça fonctionne

Les Boosting Groups ne prennent en charge que la priorisation positive. Vous pouvez les utiliser pour promouvoir des stations, mais pas pour les éviter ou les exclure. Utilisées seules, les stations boostées sont prioritaires sur toutes les autres stations le long de l'itinéraire.

Lorsqu'ils sont combinés aux préférences d'opérateurs, le planificateur d'itinéraire priorise les stations selon l'ordre de priorité suivant (du plus élevé au plus faible) :

- Les Boosting Groups actifs sont des stations boostées individuellement. Ils remplacent toutes les préférences d'opérateurs, même si l'opérateur de la station est défini sur `avoid` ou `excluded`.
- Les opérateurs préférés (`high`, `medium`, `low`) sont les stations appartenant à des réseaux de recharge préférés.
- Les stations non classées sont des stations standard auxquelles aucun groupe de boost ni aucune préférence d'opérateur ne s'applique.
- Les opérateurs dépriorisés (`avoid`) sont les stations appartenant à des opérateurs marqués comme à éviter. Elles ne sont utilisées que lorsqu'il n'existe aucune meilleure option.

Comme les préférences d'opérateurs, le boost de stations fonctionne au mieux. Le planificateur d'itinéraire équilibre la priorité des stations avec la densité de stations et l'impact du détour, de sorte que la sélection d'une station boostée n'aboutisse jamais à un itinéraire inefficace.

## Exemples

<details>
  <summary>Calculer un itinéraire avec des Boosting Groups actifs</summary>

  Comme les Boosting Groups sont appliqués automatiquement au niveau du projet, il vous suffit d'envoyer une mutation `createRoute` standard. Tous les Boosting Groups actifs sont priorisés automatiquement.

```graphql Example request
mutation CreateRoute {
  createRoute(
    input: {
      vehicle: { id: "607823b2c246f9001b97b1a2" }
      origin: {
        type: Feature
        geometry: { type: Point, coordinates: [4.895168, 52.370216] }
      }
      destination: {
        type: Feature
        geometry: { type: Point, coordinates: [6.773456, 51.227741] }
      }
    }
  ) {
    id
    status
  }
}
```
</details>

<details>
  <summary>Vérifier si les stations recommandées appartiennent à un Boosting Group</summary>

  Lors de la récupération de l'itinéraire calculé avec `getRoute` ou la souscription `route`, demandez `boosting_group_ids` sur la station du tronçon pour voir quels Boosting Groups actifs correspondent à cet arrêt.

```graphql Example request {{ mark: [11] }}
query GetRoute {
  getRoute(id: "6527e1f1a8b4c2d3e4f5a6b7") {
    status
    route {
      id
      legs {
        origin {
          properties {
            station_id
            station {
              boosting_group_ids
            }
          }
        }
      }
    }
  }
}
```
</details>
