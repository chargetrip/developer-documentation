title: "Route"

Planning routes for EVs comes with unique challenges. Battery capacity, real-world energy consumption, topography, weather, and charging network availability all determine whether a vehicle will reach its destination.

The Route API considers all these variables to find optimal EV routes. Using a world-class energy consumption model, it automatically places charging stops exactly when and where they're needed. Routes are fully customizable, so you can fine-tune them to fit your own business rules.

## How it works

To ensure high performance, the Route API operates asynchronously. Creating and retrieving a route happen in separate steps.

1. **Create a route**
   Call the `createRoute` mutation with at least a `vehicle`, `origin`, and `destination`. The mutation returns a route `id` right away, which you'll use in the next step to track and retrieve the route. Many more customization options are available, see [customize your route](#customize-your-route) below.
2. **Open a subscription**
   Subscribe to the `route` subscription using the `id` from the previous step. While the route is being calculated, the subscription pushes status updates you can use to drive an async loading state in your UI.
3. **Render the result**
   Once the route's `status` resolves to `done`, `error`, or `not_found`, render the corresponding UI for that outcome.
4. **Re-fetch a finished route**
   A route that has reached a final status is already precomputed. If you need to display it again later, for example after navigating back to it, use the `getRoute` query instead of opening a new subscription.

> [!WARNING] Hybrid vehicles
> Hybrid and plug-in hybrid vehicles don't rely solely on their battery, so their routes don't include charging stops.

## Customize your route

### Operator preferences

Operator preferences give you fine-grained control over which operators the routing service selects for charging stops. You can prioritize, require, avoid or exclude operators based on your business rules and network agreements.

#### Configuration Levels

Operator preferences can be configured at two levels:

1. **Project level (Chargetrip Dashboard):** Configured under **Project > Advanced > Station operator preferences**.
   - **Excluded** and **Avoided** operators configured here apply automatically to every route calculated under your project.
   - **Ranked** operators configured here define your project's operator priority tiers, but **they are only activated when you specify how they should be enforced** (`preferred` or `required`) in your `createRoute` request. If no ranking type is passed in the request, dashboard-ranked operators are treated as standard operators.
2. **Route request level (`createRoute` input):** Passed dynamically in the `operators` field of `createRoute`. Use this level to:
   - Activate your project's dashboard operator rankings by setting `ranking.type` to either `preferred` or `required`.
   - Override project-level settings (e.g., passing `avoid` in the request overrides project-level `avoid`).
   - Define user-selected operators on a per-request basis (e.g., user-selected operators).

> [!NOTE]
> **Override hierarchy**  
> When the same preference type is set in both project and request-level settings, request-level settings override project-level settings for that specific category (e.g., request-level `avoid` overrides project-level `avoid`, while project-level `exclude` remains active).

---

#### How Dashboard Operator Categories Behave

In the dashboard, operators can be assigned to one of three categories per country:

| Dashboard Category | Automatic Behavior | How to Enforce in `createRoute` |
|:---|:---|:---|
| **Excluded** | **Always active.** Stations from these operators will never be used in any route. | Can be overridden via `input.operators.exclude` in the request. |
| **Avoided** | **Always active.** Stations from these operators are avoided and only used as if no  . | Can be overridden via `operators.avoid` in the request. |
| **Ranked** | **Inactive by default.** Defining ranked tiers in the dashboard does not affect routes until the specific type of prefence is specified in the request. | Pass `operators.ranking.type` (`preferred` or `required`) in `createRoute`. Can be overridden via `operators.levels.` in the request.  |

#### Activating Dashboard-Ranked Operators

When activating ranked operators in your route request, you must specify the enforcement type:

- **`preferred`**: The algorithm actively prioritizes your dashboard-ranked operators according to their rank level, but can still pick other non-ranked operators if needed to prevent stranding or unreasonable detours.
- **`required`**: Route generation is strictly confined to your dashboard-ranked operators. Non-ranked, avoided, and excluded operators will not be used under any circumstances.

> [!WARNING]
> **Caution with `required`**  
> If your required operators do not have sufficient charger density along the journey, route calculation will fail with a `not_found` status.

### Operator Preference Examples

#### Option A: Activating Dashboard Rankings as Preferred (Prioritized with Fallback)

This configuration prioritizes operators ranked in your dashboard while still allowing non-ranked operators to be used if there are no time efficient alternatives:

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "x-client-id: <YOUR_CLIENT_ID>" \
  -H "x-app-id: <YOUR_APP_ID>" \
  -d '{
    "query": "mutation CreatePreferredRoute($input: CreateRouteInput!) { createRoute(input: $input) }",
    "variables": {
      "input": {
        "vehicle": "607823b2c246f9001b97b1a2",
        "origin": {
          "type": "Feature",
          "geometry": { "type": "Point", "coordinates": [4.895168, 52.370216] }
        },
        "destination": {
          "type": "Feature",
          "geometry": { "type": "Point", "coordinates": [2.352222, 48.856614] }
        },
        "operators": {
          "ranking": {
            "type": "preferred"
          }
        }
      }
    }
  }' \
  https://api.chargetrip.io/graphql
```

*Outcome: The route prioritizes operators ranked in your dashboard. If charging density is insufficient, unranked or avoided operators can still be selected to complete the route. *

---

#### Option B: Activating Dashboard Rankings as Required (Strict Whitelist)

This configuration restricts charging stops exclusively to the operators ranked in your dashboard project settings:

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "x-client-id: <YOUR_CLIENT_ID>" \
  -H "x-app-id: <YOUR_APP_ID>" \
  -d '{
    "query": "mutation CreateStrictRoute($input: CreateRouteInput!) { createRoute(input: $input) }",
    "variables": {
      "input": {
        "vehicle": "607823b2c246f9001b97b1a2",
        "origin": {
          "type": "Feature",
          "geometry": { "type": "Point", "coordinates": [4.895168, 52.370216] }
        },
        "destination": {
          "type": "Feature",
          "geometry": { "type": "Point", "coordinates": [2.352222, 48.856614] }
        },
        "operators": {
          "ranking": {
            "type": "required"
          }
        }
      }
    }
  }' \
  https://api.chargetrip.io/graphql
```

*Outcome: Only stations belonging to the ranked operators in your dashboard will be selected in the routes. Avoided, excluded, and unranked operators are excluded entirely.*

---

#### Option C: Dynamic Per-Request Ranking, Avoidance, and Exclusion

You can also pass custom operator tiers, avoidances, and exclusions directly in the mutation input without relying on dashboard rankings:

```graphql
mutation CreateCustomRoute($input: CreateRouteInput!) {
  createRoute(
    input: {
      vehicle: "607823b2c246f9001b97b1a2"
      origin: {
        type: Feature
        geometry: { type: Point, coordinates: [4.895168, 52.370216] }
      }
      destination: {
        type: Feature
        geometry: { type: Point, coordinates: [2.352222, 48.856614] }
      }
      operators: {
        ranking: {
          type: preferred
          level: {
            high: [
              { id: "5e8c22366f9c5f23ab0eff01", countries: ["NL", "DE"] }
            ]
            medium: [
              { id: "5e8c22366f9c5f23ab0eff02" }
            ]
          }
        }
        avoid: [
          { id: "5e8c22366f9c5f23ab0eff03" }
        ]
        exclude: [
          { id: "5e8c22366f9c5f23ab0eff04" }
        ]
      }
    }
  )
}
```

*Outcome: All existing project-level operator preferences are overridden by the settings used at the request level.*

`createRoute` accepts a range of optional input to fine-tune how a route is calculated. More details on each field can be found in the [API reference](/api-reference/route/mutation-create-route).

| Feature | Description |
| --- | --- |
| [Waypoints](/api-reference/route/mutation-create-route#arg-input-via) | Add intermediate stops. Provide `via.properties.station.station_id` to force a charging stop at a specific station, or only `via.geometry` for a plain transit point with no charging. |
| [Stop duration](/api-reference/route/mutation-create-route#arg-input-via-properties-station-stop_duration) | Set how long, in seconds, the vehicle stays at a waypoint or the destination, using `properties.station.stop_duration` or `properties.location.stop_duration`. |
| [Highway charging](/api-reference/route/mutation-create-route#arg-input-station_preferences) | Prioritize charging stations located directly on the highway with `station_preferences.prefer_highway_charging`, avoiding stops that require exiting the highway. |
| [Weather](/api-reference/route/mutation-create-route#arg-input-weather) | Apply a weather preset or custom weather conditions to the consumption model. Defaults to real-time weather data. |
| [Season](/api-reference/route/mutation-create-route#arg-input-season) | Assume `summer`, `winter`, or `current` weather conditions, as a simpler alternative to `weather`. |
| [Route features to avoid](/api-reference/route/mutation-create-route#arg-input-avoid) | Avoid `toll_road` or `ferry` on a best effort basis. |
| [Operator ranking](/api-reference/route/mutation-create-route#arg-input-operators-ranking) | Prefer specific charging networks with `type: preferred`, or restrict routing to only those networks with `type: required`. Rank operators as `high`, `medium`, or `low`, and scope a ranking to specific countries per operator. |
| [Operator exclusions](/api-reference/route/mutation-create-route#arg-input-operators-exclude) | Exclude an operator entirely from the route with `operators.exclude`. Falls back to your project's dashboard configuration when not set at the request level. |
| [Operator avoidance](/api-reference/route/mutation-create-route#arg-input-operators-avoid) | Avoid an operator without excluding it outright, using `operators.avoid`. |
| [Alternative charging stations](/api-reference/route/mutation-create-route#arg-input-alternative_station_radius) | Search for alternative charging stations within a radius between 500 and 5000 meters along the route. |
| [Alternative routes](/api-reference/route/mutation-create-route#arg-input-alternative_routes) | Request additional route options, on a best effort basis. Set to `0` to calculate only the recommended route. |
| [Driving preferences](/api-reference/route/mutation-create-route#arg-input-driving_preferences) | Adjust the driving style with `speed_factor` or `maximum_speed`, or pick a `style` of `eco` or `sport`. |
| [Traffic awareness](/api-reference/route/mutation-create-route#arg-input-traffic_aware) | Take real-time traffic congestion into account. Contact support to enable this for your project. |
| [Departure time](/api-reference/route/mutation-create-route#arg-input-departure_time) | Calculate expected arrival times using real-time traffic and historical, current, or forecasted weather. |
| [Destination as a station](/api-reference/route/mutation-create-route#arg-input-destination-properties-station) | Set a specific station as the route's destination. This is treated as a non-charging stop. |
| [Vehicle load per waypoint](/api-reference/route/mutation-create-route#arg-input-origin-properties-vehicle) | Set `occupants`, `total_occupant_weight`, and `total_cargo_weight` on `origin` or `via`. These propagate through the rest of the journey, and can be overridden at any later via point. |
| [Minimum charging power](/api-reference/route/mutation-create-route#arg-input-vehicle-charging-minimum_power) | By default, routing excludes connectors below 43 kW. Set a different minimum to match your vehicle's charging speed. Higher-rated chargers are still selected even if your vehicle charges slower than their maximum rate. |
