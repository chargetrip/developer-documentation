# Dettagli del percorso

Esegui la migrazione entro: Q1 2027

Passa dal servizio Route legacy alla versione più recente. Il nuovo servizio offre uno schema riorganizzato, preferenze degli operatori per paese, un calcolo del percorso più rapido e maggiore manutenibilità.

## Operazioni

| Precedente         | Nuovo                                                 |
| ------------------ | ------------------------------------------------------|
| `route`            | [`getRoute`](/api-reference/core/route/query-get-route)     |
| `routeUpdatedById`  | [`route`](/api-reference/core/route/subscription-route)     |

## Modifiche generali allo schema

- **Tipizzazione esplicita**: i campi JSON in precedenza flessibili sono ora tipizzati esplicitamente nello schema per migliorare struttura e validazione.
- **Convenzioni di denominazione**: i campi ora usano `snake_case` invece di `camelCase`.
- **Supporto delle unità**: gli input numerici ora supportano diversi tipi di unità, espressi come oggetto con `value`, `type` e un `source` opzionale (`manual`, `telemetry` o `default`).

## Modifiche a query e subscription

La denominazione e il raggruppamento dei campi sono stati rivisti e i campi ridondanti sono stati rimossi. La risposta ora include l'input originale arricchito con i valori predefiniti, così può essere riutilizzato per futuri ricalcoli del percorso.

### Livello superiore

Al livello superiore, la maggior parte dei campi si sposta sotto `recommended`, mentre gli input `ev`, `telemetry` e `routeRequest` vengono riuniti in un unico oggetto `request_input`.

| Campo          | Spostato in            |
| -------------- | ---------------------- |
| `route`        | `recommended`          |
| `alternatives` | Rimosso                |
| `ev`           | `request_input`        |
| `telemetry`    | `request_input`        |
| `routeRequest` | `request_input`        |
| `app`          | `meta.app_id`          |
| `status`       | Invariato              |

### Percorso

A livello di percorso, la maggior parte dei campi si sposta sotto `recommended`, mantenendo i propri nomi, insieme ad alcune rinomine esplicite.

| Campo                 | Spostato in                          |
| --------------------- | ------------------------------------ |
| `rangeStart*`         | `range_at_origin`                    |
| `rangeEnd*`           | `range_at_destination`               |
| `charges`             | `recommended.charges`                |
| `distance`            | `recommended.distance`               |
| `consumption`         | `recommended.consumption`            |
| `chargeTime`          | `recommended.durations.charging`     |
| `polyline`            | `recommended.polyline`               |
| `pathPlot`            | `recommended.path_plot`              |
| `legs`                | `recommended.legs`                   |
| `tags`                | `recommended.tags`                   |
| `instructions`        | Rimosso                              |
| `amenityRanking`      | Rimosso                              |
| `stationsAlongRoute`  | `recommended.alternative_stations`   |

### Tratte

A livello di tratta, le autonomie seguono le stesse rinomine del percorso, mentre i dettagli su occupanti e carico si spostano nelle proprietà di posizione `origin` e `via` di ciascuna tratta.

| Campo         | Spostato in                             |
| ------------- | --------------------------------------- |
| `rangeStart*` | `range_at_origin`                       |
| `rangeEnd*`   | `range_at_destination`                  |
| `steps`       | `sections`                              |
| `stationId`   | `recommended.legs.station.station_id`   |

Le tratte ottengono inoltre un nuovo campo `range_after_charge`.

## Modifiche in evidenza

La risposta introduce anche una nuova struttura, più organizzata, per le sezioni del percorso. È descritta più in dettaglio di seguito.

### Sezioni

I passaggi (steps) sono stati sostituiti dalle sezioni, che forniscono informazioni più granulari, inclusi i dettagli di origine e destinazione di ciascuna sezione.

```graphql Sections {{ mark: [1,13,14,26,27] }}
sections {
  type
  tags
  polyline(decimals: five)
  distance(unit: meter)
  duration
  consumption
  origin {
    id
    type
    properties {
      occupants
      total_occupant_weight
      total_cargo_weight
    }
    geometry {
      type
      coordinates
    }
  }
  destination {
    id
    type
    properties {
      occupants
      total_occupant_weight
      total_cargo_weight
    }
    geometry {
      coordinates
      type
    }
  }
}
```
