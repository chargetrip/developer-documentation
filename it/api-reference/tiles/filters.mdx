I filtri permettono alle applicazioni di restringere le stazioni di ricarica restituite dall'API del servizio Tile. Oltre a nascondere i risultati non corrispondenti, alcuni filtri trasformano anche i dati delle stazioni per garantire che la risposta sia pertinente al contesto.

## Come i filtri influenzano i dati

Quando una richiesta include dei filtri, il servizio Tile esegue due operazioni distinte:

1. **Esclusione delle stazioni non corrispondenti**
   Qualsiasi stazione che non soddisfa i criteri di filtro specificati viene rimossa del tutto dalla risposta. Questa operazione avviene quando vengono usati filtri a livello di stazione o a livello di EVSE.
2. **Trasformazione dei dati**
   Quando vengono forniti determinati parametri di filtro, il servizio Tile ricalcola alcune proprietà dinamiche della stazione. Questa operazione avviene quando vengono usati filtri a livello di EVSE.

## Implementazione

I parametri di filtro possono essere aggiunti all'URL della richiesta come stringhe di query a qualsiasi endpoint del servizio Tile (MVT, JSON o Conteggio). Se non viene applicato alcun filtro, vengono restituite tutte le stazioni di ricarica disponibili e non viene eseguita alcuna trasformazione dei dati.

```bash Tile / Filter / Example
https://api.chargetrip.io/v2/station/..../?{filter_1}&{filter_2}&{filter_n}
```

## Livelli

I filtri possono esistere su due livelli: a livello di EVSE o a livello di stazione, ciascuno con il proprio impatto e i propri risultati come descritto di seguito.

### Livello stazione

Filtri che valutano gli attributi globali della stazione. Questi filtri sono solo di esclusione: escludono le stazioni non corrispondenti ma non modificano mai i campi di dati restituiti.

`amenities` · `enum` · [Mostra URL di esempio](tip:https://api.chargetrip.io/v2/station?amenities[]=HOTEL)
: Filtra per includere solo le stazioni che offrono i servizi specificati.
: `HOTEL`, `SHOPPING`, `BATHROOM`, `SUPERMARKET`, `PLAYGROUND`, `PHARMACY`, `MUSEUM`, `COFFEE`, `RESTAURANT`

`preferred_operators` · `boolean` · [Mostra URL di esempio](tip:https://api.chargetrip.io/v2/station?preferred_operators=true)
: Filtra per includere solo le stazioni gestite da operatori configurati come preferiti. Gli operatori preferiti possono essere impostati nelle impostazioni del progetto nel dashboard.
: `true`, `false`

`truck_dedicated` · `boolean` · [Mostra URL di esempio](tip:https://api.chargetrip.io/v2/station?truck_dedicated=true)
: Filtra per includere solo le stazioni dedicate o destinate principalmente alla ricarica di camion. **Applicabile solo se viene utilizzato il database di stazioni Eco-Movement; in caso contrario viene ignorato.**
: `true`, `false`

### Livello EVSE

Filtri che valutano le specifiche capacità di ricarica della stazione. Questi filtri eseguono esclusione e [trasformazione](/api-reference/tiles/filters#esempi-di-trasformazione-dei-dati): le stazioni non corrispondenti vengono escluse e per quelle corrispondenti i campi dinamici vengono ricalcolati.

`connectors` · `enum` · [Mostra URL di esempio](tip:https://api.chargetrip.io/v2/station?connectors[]=CHADEMO)
: Filtra per includere solo le stazioni che hanno EVSE con i tipi di connettore specificati. Accetta un array di stringhe con qualsiasi valore di connettore OCPI 2.2.1.
: `CHADEMO`, `DOMESTIC_A`, `DOMESTIC_B`, `DOMESTIC_C`, `DOMESTIC_D`, `DOMESTIC_E`, `DOMESTIC_F`, `DOMESTIC_G`, `DOMESTIC_H`, `DOMESTIC_I`, `DOMESTIC_J`, `DOMESTIC_K`,
`DOMESTIC_L`, `DOMESTIC_M`, `DOMESTIC_N`, `DOMESTIC_O`, `IEC_60309_2_single_16`, `IEC_60309_2_three_16`, `IEC_60309_2_three_32`, `IEC_60309_2_three_64`, `IEC_62196_T1`,
`IEC_62196_T1_COMBO`, `IEC_62196_T2`, `IEC_62196_T2_COMBO`, `IEC_62196_T3A`, `IEC_62196_T3C`, `PANTOGRAPH_BOTTOM_UP`, `PANTOGRAPH_TOP_DOWN`, `TESLA_R`, `TESLA_S`, `GB_T`,
`CHAOJI`, `NEMA_5_20`, `NEMA_6_30`, `NEMA_6_50`, `NEMA_10_30`, `NEMA_10_50`, `NEMA_14_30`, `NEMA_14_50`

### Esempi di trasformazione dei dati

Alcuni output vengono ricalcolati quando si applicano filtri a livello di EVSE. Questi campi vengono "trasformati" per ignorare i connettori che non corrispondono ai criteri di ricerca dell'utente.
Questi campi di output "dinamici" sono `connector_maximum_power` e `evse_status_*`.

<details>
  <summary>Stesso tipo di filtro, valori diversi</summary>
  La richiesta include un filtro per il connettore CHADEMO. La stazione è inclusa perché ha un connettore CHADEMO, ma i campi dinamici vengono trasformati per ignorare i caricatori Combo Type 1.

```bash Example URL
https://api.chargetrip.io/v2/station?connectors[]=IEC_62196_T1_COMBO&connectors[]=CHADEMO
```

```json Response
{
  "id": "station_a",
  // Static: Remains 150 kW (This represents the station maximum power across all connectors)
  "station_maximum_power": 150,
  // Dynamic: Adjusted to 100 kW (Max power of the CHADEMO connector)
  "connector_maximum_power": 100,
  // Dynamic: Counts the 1 CHADEMO chargers
  "evse_status_out_of_order": 0,
  // Dynamic: 0, because the charging Type 1 plugs are filtered out
  "evse_status_available": 1
}
```
</details>
