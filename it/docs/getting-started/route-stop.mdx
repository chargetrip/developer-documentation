---
title: Percorso con tappe
description: "Aggiungi tappe intermedie tra origine e destinazione con via, usando tappe di posizione o di ricarica per scenari di viaggio reali."
---

Quando calcoli un percorso EV con la Route API di Chargetrip, puoi aggiungere tappe intermedie tra l'origine e la destinazione usando `via`.

Le tappe ti permettono di personalizzare il calcolo del percorso per scenari di viaggio reali, ad esempio ricaricare in una stazione di ricarica preferita, far salire dei passeggeri o fermarsi a un ristorante.


## Tipi di tappe

Chargetrip supporta due tipi di tappe intermedie:

| Tappa | Ricarica |  Campo di input | Scopo |
| :--- | :--- | :--- | :--- |
| **Località** | No |  `via.geometry`| Tappa geografica (ritiro, consegna, deviazione panoramica, pausa caffè).
| **Stazione** | Sì | `via.properties.station.station_id`| Stazione di ricarica selezionata esplicitamente.


## Durata della tappa

Puoi configurare la durata di ogni tappa. A seconda del tipo di tappa (con o senza ricarica), `stop_duration` viene configurato in posizioni diverse e ha comportamenti diversi:

### 1. Nelle tappe senza ricarica

La durata della tappa viene configurata in `input.via.properties.location.stop_duration`. Questa durata rappresenta la **durata esatta della tappa** e viene aggiunta direttamente alla durata totale del viaggio senza influire sul tempo di ricarica o di guida del veicolo.

### 2. Nelle tappe con ricarica

La durata della tappa viene configurata in `input.via.properties.station.stop_duration`. Questo valore rappresenta **la durata minima della tappa**. Il veicolo rimane alla stazione almeno per questo tempo, ma il pianificatore del percorso può prolungare la sosta in base al `charge_mode` configurato:

  * `ALWAYS_TO_MAX_CHARGE`: Prolunga il tempo di ricarica, se necessario, per raggiungere lo SoC massimo configurato. Se il `stop_duration` richiesto supera il tempo necessario per raggiungere lo SoC massimo, il tempo rimanente viene registrato come sosta inattiva.

  * `OPTIMIZE_TRAVEL_TIME`: Prolunga la sosta oltre `stop_duration` solo se questo riduce il tempo complessivo del viaggio (ad esempio eliminando una successiva tappa di ricarica). In caso contrario, ricarica per l'esatta durata richiesta. Se il `stop_duration` richiesto supera il tempo necessario per raggiungere lo SoC massimo, il tempo rimanente viene registrato come sosta inattiva.

Se non viene fornito alcun valore, il pianificatore ottimizza la durata della ricarica basandosi esclusivamente sul `charge_mode` del percorso.


## Aggiungere una stazione a un percorso esistente

Uno scenario comune: un utente sceglie una stazione di ricarica per un percorso che ha già delle tappe, ad esempio una stazione alternativa mostrata nella tua UI. La soluzione no-code usa questo approccio per aggiungere automaticamente una stazione come tappa `via`, senza logica di riordino, in modo che il percorso si aggiorni senza interruzioni.

L'ordine dell'array `via` è l'ordine in cui le tappe vengono raggiunte. Una stazione aggiunta in fondo viene raggiunta per ultima, anche se si trova vicino all'inizio del percorso. Per inserirla nella posizione giusta, confronta la posizione della stazione con i punti di passaggio già presenti sul percorso:

1. **Raccogli i punti di passaggio in ordine.** Prendi `origin`, ogni tappa `via` esistente e `destination` dal `request_input` del percorso che vuoi modificare. Ogni punto di passaggio nel `request_input` ha la sua `geometry` disponibile, comprese le tappe create solo con una `station_id`.

2. **Traccia una linea che attraversa i punti di passaggio.** Collega i punti di passaggio in ordine per formare una linea. Ogni parte di questa linea tra due punti di passaggio è un segmento.

3. **Trova il segmento più vicino alla stazione.** Usa una libreria geospaziale per trovare il punto della linea più vicino alle coordinate della stazione. <a href="https://turfjs.org" target="_blank" rel="noopener noreferrer">turf.js</a> offre ad esempio `nearestPointOnLine`, che restituisce anche l'indice del segmento che contiene questo punto. Quell'indice è l'indice del punto di passaggio da cui inizia il segmento.

4. **Inserisci la stazione dopo quel punto di passaggio.** L'elenco dei punti di passaggio inizia con `origin`, quindi l'indice di un punto di passaggio in questo elenco corrisponde alla posizione in cui inserire un nuovo elemento in `via` per ritrovarlo subito dopo. Un indice `0` significa che la stazione viene inserita come prima tappa.

5. **Non inserire mai dopo la destinazione.** Quando il punto più vicino si trova sull'ultimo segmento, l'indice può puntare a `destination`. Inserirla lì collocherebbe la stazione dopo la fine del percorso. Usa invece il punto di passaggio precedente, così la stazione viene inserita come ultima tappa prima di `destination`.

### Da tenere a mente

* La linea collega i punti di passaggio con segmenti rettilinei e non segue le strade del percorso. Le stazioni alternative si trovano sempre in un corridoio di 5-10 km attorno al percorso, quindi non se ne discostano mai di molto e il segmento più vicino è per lo più accurato. Per le stazioni fuori da questo corridoio potrebbero essere più adatte altre soluzioni.
* Il `request_input` del percorso è la fonte di riferimento. Costruisci la nuova richiesta a partire da esso e lascia invariati tutti gli altri campi, come `vehicle` e le impostazioni `charging`.

## Esempi

<details>
  <summary>Calcola un percorso con una tappa senza ricarica di 30 minuti.</summary>
  In questa tappa è stato aggiunto un `stop_duration` di 1800 secondi (30 minuti). Questa sarà la durata della tappa, poiché non può esserci alcun ulteriore vantaggio.

```graphql Esempio di richiesta
mutation CreateRouteWithWaypoint {
  createRoute(
    input: {
      vehicle: {
        id: "60b8d5a2f1c8e9001b9e2831"
        charging: { mode: OPTIMIZE_TRAVEL_TIME }
      }
      origin: {
        type: Point
        coordinates: [4.9041, 52.3676]
      }
      destination: {
        type: Point
        coordinates: [6.9583, 50.9375]
      }
      via: [
        {
          geometry: {
            type: Point
            coordinates: [5.1214, 52.0907] # Utrecht
          }
          properties: {
            location: {
              name: "Utrecht Central"
              stop_duration: 1800 # 30 minutes in seconds
            }
          }
        }
      ]
    }
  ) {
    id
    status
  }
}
```
</details>

  <summary>Calcola un percorso con una tappa di ricarica di almeno 30 minuti.</summary>
  In questa tappa è stato aggiunto un `stop_duration` di 1800 secondi (30 minuti). Questa sarà la durata **minima** della tappa. Se ricaricare più a lungo è vantaggioso per l'itinerario, la durata aumenterà.
  
```graphql Esempio di richiesta
mutation CreateRouteWithChargingVia {
  createRoute(
    input: {
      vehicle: {
        id: "60b8d5a2f1c8e9001b9e2831"
        charging: { mode: OPTIMIZE_TRAVEL_TIME }
      }
      origin: {
        type: Point
        coordinates: [4.9041, 52.3676]
      }
      destination: {
        type: Point
        coordinates: [6.9583, 50.9375]
      }
      via: [
        {
          properties: {
            station: {
              station_id: "5e849ea2837bc43df65d19a2"
              stop_duration: 1800
            }
          }
        }
      ]
    }
  ) {
    id
    status
  }
}
```
</details>
