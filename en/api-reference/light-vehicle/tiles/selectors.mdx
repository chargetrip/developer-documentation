title: Selectors
description: "Include additional data points in the MVT and JSON tile responses with selectors, while keeping tile payloads small and fast."

---

To optimize network latency and rendering performance, Chargetrip MVT and JSON tile services return a minimal payload by default. This default payload provides essential geometry and clustering data needed to render map tiles quickly.

By using selectors, you can request the specific station data attributes your client application needs without incurring unnecessary payload overhead.



## Implementation

To request specific station attributes, append the `station_properties[]` query parameter to your tile request URL. Repeat the parameter for each selector you want to include:

```bash Tile / Selectors / Example
https://api.chargetrip.io/v2/station/...?station_properties[]={selector1}&station_properties[]={selector2}&station_properties[]={selector3}
```

## Available selectors
Selectors only apply to **station features**, cluster features are unaffected and always return `count` and `expansion_zoom`.


`count` · `integer` · <span class="text-accent">default</span>
: The count of stations within a cluster. A count of 1 indicates a Station feature, whereas a count greater than 1 indicates a Cluster feature.

`id` · `string` · <span class="text-accent">default</span>
: The unique Chargetrip identifier of the station. Only applicable to [MVT Tiles](/api-reference/light-vehicle/tiles/mvt).

`lng` · `float`
: The longitude of the station. Only applicable to [MVT Tiles](/api-reference/light-vehicle/tiles/mvt).

`lat` · `float`
: The latitude of the station. Only applicable to [MVT Tiles](/api-reference/light-vehicle/tiles/mvt).

`operator_id` · `string`
: The unique Chargetrip identifier of the operator of the station. Not returned if the operator is unknown.

`station_maximum_power` · `integer`
: The station’s maximum charging power (in kW) available at the station. This value is static and always reflects the station's highest capability, regardless of connector filters.

`connector_maximum_power` · `integer`
: The maximum charging power (in kW) available from the connectors matching the `connectors[]` filter. If no filter is provided, all connectors are considered and it matches `station_maximum_power`.

`preferred_operator` · `boolean`
: Indicates if the operator of a station is a preferred operator. Operator preferences can be managed in [Chargetrip's dashboard](https://account.chargetrip.io/projects).

`connector_minimum_energy_price` · `float` · [beta](tip:Beta;;This field is in beta and may change before it becomes stable.)
: The lowest energy price among the station's connectors. Not returned if unavailable. Only applicable if the Eco-Movement station database is used; otherwise, it is ignored.

`connector_maximum_energy_price` · `float` · [beta](tip:Beta;;This field is in beta and may change before it becomes stable.)
: The highest energy price among the station's connectors. Not returned if unavailable. Only applicable if the Eco-Movement station database is used; otherwise, it is ignored.

`price_vat` · `float` · [beta](tip:Beta;;This field is in beta and may change before it becomes stable.)
: The VAT applied to the price. Not returned if unavailable. Only applicable if the Eco-Movement station database is used; otherwise, it is ignored.

`price_valid_until` · `string` · [beta](tip:Beta;;This field is in beta and may change before it becomes stable.)
: The date and time until which the price is valid. Not returned if unavailable. Only applicable if the Eco-Movement station database is used; otherwise, it is ignored.

`price_original_currency` · `string` · [beta](tip:Beta;;This field is in beta and may change before it becomes stable.)
: The currency the price was originally defined in, before conversion to `currency`. Not returned if unavailable. Only applicable if the Eco-Movement station database is used; otherwise, it is ignored.

`price_conversion_rate` · `float` · [beta](tip:Beta;;This field is in beta and may change before it becomes stable.)
: The rate used to convert the price from its original currency to `currency`. Not returned if unavailable. Only applicable if the Eco-Movement station database is used; otherwise, it is ignored.

`evses_blocked` · `integer`
: Number of EVSEs physically or electronically blocked. If a `connectors[]` filter is provided, it only counts blocked EVSEs that have at least one of selected connector types.

`evses_planned` · `integer`
: Number of EVSEs in planned status. If a `connectors[]` filter is provided, it only counts planned EVSEs that have at least one of selected connector types.

`evses_available` · `integer`
: Number of EVSEs in status available. If a `connectors[]` filter is provided, it only counts available EVSEs that have at least one of selected connector types.

`evses_charging` · `integer`
: Number of EVSEs currently occupied. If a `connectors[]` filter is provided, it only counts charging EVSEs that have at least one of selected connector types.

`evses_unknown` · `integer`
: Number of EVSEs whose real-time status is currently unknown. If a `connectors[]` filter is provided, it only counts unknown EVSEs that have at least one of selected connector types.

`evses_reserved` · `integer`
: Number of EVSEs reserved for a driver. If a `connectors[]` filter is provided, it only counts reserved EVSEs that have at least one of selected connector types.

`evses_out_of_order` · `integer`
: Number of EVSEs marked as out of order. If a `connectors[]` filter is provided, it only counts out of order EVSEs that have at least one of selected connector types.

`evses_inoperative` · `integer`
: Number of EVSEs temporarily inoperative. If a `connectors[]` filter is provided, it only counts inoperative EVSEs that have at least one of selected connector types.

## Examples

<details>
  <summary>Request station power and operator preference in JSON tiles</summary>

In JSON tiles, the mandatory feature structure (`type`, `geometry`, `id`) is always preserved on station features, while `properties` contains only the requested selectors (the default `count` property is omitted because it was not requested). Cluster features are unaffected by selectors and still return `count` and `expansion_zoom`.

```bash Example request {{ mark: [2,3] }}
https://api.chargetrip.io/v2/station/10/582/325/tile.json
  ?station_properties[]=station_maximum_power
  &station_properties[]=preferred_operator
```

```json Example response {{ mark: [13,14,15,16] }}
{
  "type": "FeatureCollection",
  "features": [
    // Station feature (count = 1)
    {
      "id": "5e5f3e8f8e0c1a0012345678",
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [4.895168, 52.370216]
      },
      "properties": {
        "station_maximum_power": 350,
        "preferred_operator": true
      }
    },
   // Cluster feature (unaffected by selectors)
    {
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [5.1214, 52.0907]
      },
      "properties": {
        "count": 4,
        "expansion_zoom": 14
      }
    }
  ]
}
```

</details>

<details>
  <summary>Request station ID, power and operator preference in MVT vector tiles</summary>

 In MVT tiles, only explicitly requested selectors are encoded into the station feature (omitting the default `count` property), while cluster features are unaffected by selectors and always retain `count` and `expansion_zoom`.

```bash Example request {{ mark: [2,3,4] }}
https://api.chargetrip.io/v2/station/10/582/325/tile.mvt
  ?station_properties[]=id
  &station_properties[]=station_maximum_power
  &station_properties[]=preferred_operator
```

```json Example response {{ mark: [2,3,4,5,6] }}
// Station feature ('count' is omitted because it wasn't requested as a selector)
{
  "id": "5e5f3e8f8e0c1a0012345678",
  "preferred_operator": true,
  "station_maximum_power": 350
}

// Cluster feature (unaffected by selectors)
{
  "count": 4,
  "expansion_zoom": 14
}
```

</details>

<details>
  <summary>Combine selectors with connector filters for real-time EVSE status</summary>

  When filtering by a specific connector type (e.g., CCS / `IEC_62196_T2_COMBO`), the `connector_maximum_power` and `evses_available` counts reflect only EVSEs matching that connector filter.

```bash Example request {{ mark: [2,3,4] }}
https://api.chargetrip.io/v2/station/10/582/325/tile.json
  ?connectors[]=IEC_62196_T2_COMBO
  &station_properties[]=connector_maximum_power
  &station_properties[]=evses_available
```

```json Example response {{ mark: [12,13,14,15] }}
{
  "type": "FeatureCollection",
  "features": [
    {
      "id": "5e5f3e8f8e0c1a0012345678",
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [4.895168, 52.370216]
      },
      "properties": {
        "connector_maximum_power": 300,
        "evses_available": 2
      }
    }
  ]
}
```
</details>
