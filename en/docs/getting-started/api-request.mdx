Once your credentials are created in the Chargetrip dashboard, you can start making authorized requests using our base URLs and required authentication headers.

## The setup


The Chargetrip API uses two distinct endpoints depending on the operation type: an HTTPS URL for queries and mutations, and a WebSocket (WSS) URL for subscriptions. You can find more information about the API in the [GraphQL API reference](/api-reference).

### Queries and mutations
Queries and mutations are executed via HTTP POST requests to the main GraphQL endpoint.


```bash GraphQL queries and mutations endpoint URL
https://api.chargetrip.io/graphql
```

### Subscriptions
Subscriptions require a persistent connection over WebSockets and can be implemented by using the `graphql-transport-ws` protocol. Learn how to use websockets in detail over [here](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API/Writing_WebSocket_client_applications).


```bash GraphQL Subscription URL
wss://api.chargetrip.io/subscription
```

> [!WARNING] graphql-ws protocol is deprecated
> The legacy graphql-ws subscription protocol is deprecated and soon will be removed. Please migrate to the graphql-transport-ws protocol to prevent subscription errors and service disruptions.


## Authorization headers

After obtaining the base URL, add the following headers to each request. Headers marked required must always be sent.

`x-client-id` · <span class="text-accent">required</span>
: A project id that contains the project configuration.

`x-app-id` · <span class="text-accent">required</span>
: An app id for security and splitting up analytics.

`x-app-identifier`
: An iOS or Android bundle identifier.

`x-app-fingerprint`
: An Android SHA fingerprint.

> [!TIP] Secure your keys
> For maximum security, restrict your application to machine-to-machine (M2M) access and keep credentials on your own server behind your own authentication, rather than exposing them to a browser or device. See [Security](/api-reference/api/security) for all available restriction types.

## Sending an authorized request

To communicate with the API, you must authenticate each request with the headers `x-client-id` and `x-app-id`. By default, a unique `x-app-id` is generated for each project.

```bash Example request
curl -X POST \
  -H "Content-Type: application/json" \
  -H "x-client-id: YOUR_KEY_HERE" \
  -H "x-app-id: YOUR_KEY_HERE" \
  -d '{ "query": "{ } " }' \
  https://api.chargetrip.io/graphql
```
