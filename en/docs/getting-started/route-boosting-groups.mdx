---
title: Prioritize individual charging stations
---

Boosting Groups allow you to steer station selection toward specific charging locations based on your own business rules.

While [operator preferences](/docs/getting-started/route-operators) allow you to prioritize entire charging networks, Boosting Groups give you granular, station-level control. Whatever your reason for favoring these stations—such as lower pricing, low utilization, or a better commercial deal—you can boost them to the top of the station hierarchy.

## How to boost stations

To get started, simply contact [Support](https://www.chargetrip.com/contact/support) with the list of stations you want to prioritize.

Once your group is set up and enabled on your project, all routes calculated with [createRoute](/api-reference/route/mutation-create-route) will automatically use it in the background—no changes or additional parameters are needed in your API requests.

## How it works

Boosting Groups only support positive prioritization—you can use them to promote stations, but not to avoid or exclude them. When used on their own, boosted stations are prioritized over all other stations along the route.

When combined with operator preferences, the route planner prioritizes stations in the following order of priority (from highest to lowest):

- **Active Boosting Groups** — Individual boosted stations, which override all operator preferences (even if the station's operator is set to `avoid` or `excluded`).
- **Preferred operators (`high`, `medium`, `low`)** — Stations belonging to preferred charging networks.
- **Unranked stations** — Standard stations with no boosting group or operator preference applied.
- **Deprioritized operators (`avoid`)** — Stations belonging to operators marked to avoid, used only when no better options exist.

Like operator preferences, station boosting operates on a best-effort basis. The route planner balances station priority against station density and detour impact so that selecting a boosted station never results in an inefficient route.

## Examples

<details>
  <summary>Calculate a route with active boosting groups</summary>

  Because Boosting Groups are applied automatically at the project level, you only need to send a standard `createRoute` mutation. Any active Boosting Groups are prioritized automatically.

```graphql Example request
mutation CreateRoute {
  createRoute(
    input: {
      vehicle: { id: "607823b2c246f9001b97b1a2" }
      origin: {
        type: Feature
        geometry: { type: Point, coordinates: [4.895168, 52.370216] }
      }
      destination: {
        type: Feature
        geometry: { type: Point, coordinates: [6.773456, 51.227741] }
      }
    }
  ) {
    id
    status
  }
}
```
</details>

<details>
  <summary>Check if recommended stations belong to a boosting group</summary>

  When retrieving the calculated route with `getRoute` or the `route` subscription, request `boosting_group_ids` on the leg station to see which active Boosting Groups matched that stop.

```graphql Example request {{ mark: [11] }}
query GetRoute {
  getRoute(id: "6527e1f1a8b4c2d3e4f5a6b7") {
    status
    route {
      id
      legs {
        origin {
          properties {
            station_id
            station {
              boosting_group_ids
            }
          }
        }
      }
    }
  }
}
```

```json Example response

                    "66c4a912e4b0a123456789ab"
                  ]
                }

        ]
      }
    }
  }
}
```
</details>
