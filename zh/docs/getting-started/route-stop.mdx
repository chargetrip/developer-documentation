使用 Chargetrip Route API 计算电动汽车路线时，您可以使用 `via` 在起点和终点之间添加中途停靠点。

停靠点让您可以针对真实出行场景自定义路线规划，例如在偏好的充电站充电、接送乘客或在餐厅停靠。


## 停靠点类型

Chargetrip 支持两种类型的中途停靠点：

| 停靠点 | 充电 |  输入字段 | 用途 |
| :--- | :--- | :--- | :--- |
| **位置** | 否 |  `via.geometry`| 地理位置停靠点（接客、送货、风景绕行、咖啡休息）。
| **充电站** | 是 | `via.properties.station.station_id`| 明确选定的充电站。


## 停靠时长

您可以配置每个停靠点的时长。根据停靠点的类型（充电或非充电），`stop_duration` 的配置位置不同，行为也不同：

### 1. 在非充电停靠点中

停靠时长配置在 `input.via.properties.location.stop_duration`。该时长代表**确切的停靠时长**，会直接计入总行程时长，不影响车辆的充电或行驶时间。

### 2. 在充电停靠点中

停靠时长配置在 `input.via.properties.station.stop_duration`。该值代表**最短停靠时长**。车辆至少会在充电站停留这么长时间，但路线规划器可能会根据所配置的 `charge_mode` 延长停靠：

  * `ALWAYS_TO_MAX_CHARGE`：如有需要，延长充电时间以达到所配置的最大 SoC。如果请求的 `stop_duration` 超过达到最大 SoC 所需的时间，剩余时间会记录为空闲停留。

  * `OPTIMIZE_TRAVEL_TIME`：仅当延长停留可以缩短总行程时间（例如，省去后续的充电停靠）时，才会将停留时间延长到超过 `stop_duration`。否则，按请求的确切时长充电。如果请求的 `stop_duration` 超过达到最优 SoC 所需的时间，剩余时间会记录为空闲停留。

如果未提供值，规划器将完全依据路线的 `charge_mode` 来优化充电时长。


## 向现有路线添加充电站

一个常见的场景是，用户为已有停靠点的路线选择充电站，例如在您的 UI 中显示的备选充电站。无代码解决方案使用这种方法自动将充电站添加为 `via` 停靠点，无需任何重新排序逻辑，因此路线可以无缝更新。

`via` 数组的顺序就是依次访问各停靠点的顺序。追加到末尾的充电站会最后访问，即使它位于路线起点附近。要将其插入到正确的位置，请将该充电站的位置与路线上已有的途经点进行比较：

1. **按顺序收集途经点。** 从您要更改的路线的 `request_input` 中获取 `origin`、每个现有的 `via` 停靠点以及 `destination`。`request_input` 上的每个途经点都有可用的 `geometry`，包括仅使用 `station_id` 创建的停靠点。

2. **绘制一条穿过途经点的线。** 按顺序连接这些途经点，形成一条线。这条线上位于两个途经点之间的每一部分是一个线段。

3. **找到距离充电站最近的线段。** 使用地理空间库，找出这条线上距离充电站坐标最近的点。例如，<a href="https://turfjs.org" target="_blank" rel="noopener noreferrer">turf.js</a> 提供了 `nearestPointOnLine`，它还会返回包含该点的线段的索引。该索引就是该线段起始途经点的索引。

4. **将充电站插入到该途经点之后。** 途经点列表以 `origin` 开头，因此途经点在该列表中的索引，与向 `via` 中插入新项目、使其紧随该途经点之后的位置相一致。索引为 `0` 表示该充电站被插入为第一个停靠点。

5. **切勿插入到终点之后。** 当最近点位于最后一个线段上时，索引可能指向 `destination`。在此处插入会将充电站放在路线终点之后，因此请改用前一个途经点。这样，充电站会被插入为 `destination` 之前的最后一个停靠点。

### 注意事项

* 这条线用直线段连接各途经点，并不沿着路线的道路。备选充电站始终位于路线周围 5 至 10 公里的走廊范围内，因此它们不会大幅偏离路线，最近的线段大多是准确的。对于此走廊之外的充电站，其他解决方案可能更合适。
* 路线的 `request_input` 是事实来源。请基于它构建新请求，并保持所有其他字段（例如 `vehicle` 和 `charging` 设置）不变。

## 示例

<details>
  <summary>计算带有 30 分钟非充电停靠点的路线。</summary>
  在此停靠点上，添加了 1800 秒（30 分钟）的 `stop_duration`。这将是确切的停靠时长。

```graphql Example request
mutation CreateRouteWithWaypoint {
  createRoute(
    input: {
      vehicle: {
        id: "60b8d5a2f1c8e9001b9e2831"
        charging: { mode: OPTIMIZE_TRAVEL_TIME }
      }
      origin: {
        type: Point
        coordinates: [4.9041, 52.3676]
      }
      destination: {
        type: Point
        coordinates: [6.9583, 50.9375]
      }
      via: [
        {
          geometry: {
            type: Point
            coordinates: [5.1214, 52.0907] # Utrecht
          }
          properties: {
            location: {
              name: "Utrecht Central"
              stop_duration: 1800 # 30 minutes in seconds
            }
          }
        }
      ]
    }
  ) {
    id
    status
  }
}
```
</details>
