为了优化响应时间和大小，默认情况下，MVT 和 JSON API 会返回精简的响应。这种方式可确保最佳性能并减小瓦片负载大小，这对于流畅的地图交互至关重要。通过使用选择器，您可以包含应用特别需要的额外数据点。

## 可用的选择器

MVT 和 JSON 瓦片的充电站属性中列出的任何字段，都可以在其对应的服务中用作选择器，但 JSON 端点中返回的必需 GeoJSON 字段除外。

`count` · `integer` · <span class="text-accent">default</span>
: 聚合点内的充电站数量。数量为 1 表示 Station 要素，数量大于 1 表示 Cluster 要素。

`expansion_zoom` · `integer` · <span class="text-accent">default</span>
: 聚合点拆分为多个更小的聚合点或充电站时的缩放级别。

`id` · `string`
: 充电站的标识符。

`lng` · `float`
: 充电站的经度。

`lat` · `float`
: 充电站的纬度。

`station_maximum_power` · `integer`
: 充电站可提供的最大充电功率（单位 kW）。此值是静态的，始终反映充电站的最高能力，与连接器筛选无关。

`connector_maximum_power` · `integer`
: 与 `connectors[]` 筛选匹配的连接器可提供的最大充电功率（单位 kW）。如果未提供筛选，则会考虑所有连接器，并且该值与 `station_maximum_power` 相同。

`preferred_operator` · `boolean`
: 表示充电站的运营商是否为首选运营商。可以在 Dashboard 的项目级别管理首选运营商。

`evse_status_blocked` · `integer`
: 处于 blocked 状态的 EVSE 数量。如果提供了 `connectors[]` 筛选，则只统计与所选连接器类型匹配的 blocked EVSE。

`evse_status_planned` · `integer`
: 处于 planned 状态的 EVSE 数量。如果提供了 `connectors[]` 筛选，则只统计至少具有一种所选连接器类型的 planned EVSE。

`evse_status_available` · `integer`
: 处于 available 状态的 EVSE 数量。如果提供了 `connectors[]` 筛选，则只统计至少具有一种所选连接器类型的 available EVSE。

`evse_status_charging` · `integer`
: 处于 charging 状态的 EVSE 数量。如果提供了 `connectors[]` 筛选，则只统计至少具有一种所选连接器类型的 charging EVSE。

`evse_status_unknown` · `integer`
: 处于 unknown 状态的 EVSE 数量。如果提供了 `connectors[]` 筛选，则只统计至少具有一种所选连接器类型的 unknown EVSE。

`evse_status_reserved` · `integer`
: 处于 reserved 状态的 EVSE 数量。如果提供了 `connectors[]` 筛选，则只统计至少具有一种所选连接器类型的 reserved EVSE。

`evse_status_out_of_order` · `integer`
: 处于 out_of_order 状态的 EVSE 数量。如果提供了 `connectors[]` 筛选，则只统计至少具有一种所选连接器类型的 out of order EVSE。

`evse_status_inoperative` · `integer`
: 处于 inoperative 状态的 EVSE 数量。如果提供了 `connectors[]` 筛选，则只统计至少具有一种所选连接器类型的 inoperative EVSE。

## 实现

要请求特定属性，请在瓦片请求 URL 后附加 `station_properties[]` 查询参数。

```bash Tile / Selectors / Example
https://api.chargetrip.io/v2/station/.../?station_properties[]={selector1}&station_properties[]={selector2}&station_properties[]={selector3}
```

## 行为示例

提供选择器后，请求只返回指定的字段。

### GeoJSON

在 GeoJSON 端点中，无论选择了哪些选择器，必需的 GeoJSON 字段（`type`、`geometry` 和 `id`）始终会返回。

```json JSON Selectors example
{
  "type": "FeatureCollection",
  "features": [
    // Station feature
    {
      "id": "132313",
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [6.789, 52.234]
      },
      // 'count' is missing because it wasn't provided as selector
      "properties": {
        "station_maximum_power": 350,
        "preferred_operator": true
      }
    },
    // Cluster feature
    // Cluster feature is not modified, as it's not affected by the selectors.
    {
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [6.723, 50.0]
      },
      "properties": {
        "count": 3,
        "expansion_zoom": 18
      }
    }
  ]
}
```

### MVT

在 MVT 端点中，由于没有必需字段，只会返回明确选择的参数。

```json MVT Selectors example
// Station feature
// 'count' is missing because it wasn't provided as a selector.
{
  "id": "132313",
  "preferred_operator": false,
  "station_maximum_power": 350
}

// Cluster feature
// Cluster feature is not modified, as it's not affected by the selectors.
{
  "count": 3,
  "expansion_zoom": 32
}
```
