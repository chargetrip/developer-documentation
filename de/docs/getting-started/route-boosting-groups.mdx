---
title: Einzelne Ladestationen priorisieren
---

Mit Boosting Groups steuern Sie die Stationsauswahl anhand Ihrer eigenen Geschäftsregeln gezielt zu bestimmten Ladestandorten.

Während Sie mit [Betreiberpräferenzen](/docs/getting-started/route-operators) ganze Ladenetzwerke priorisieren können, bieten Boosting Groups eine granulare Steuerung auf Stationsebene. Aus welchem Grund Sie diese Stationen auch bevorzugen, etwa niedrigere Preise, geringe Auslastung oder ein besseres kommerzielles Angebot, Sie können sie an die Spitze der Stationshierarchie setzen.

## So priorisieren Sie Stationen

Wenden Sie sich zunächst einfach mit der Liste der Stationen, die Sie priorisieren möchten, an den [Support](https://www.chargetrip.com/contact/support).

Sobald Ihre Gruppe eingerichtet und für Ihr Projekt aktiviert ist, verwenden alle mit [createRoute](/api-reference/core/route/mutation-create-route) berechneten Routen sie automatisch im Hintergrund, sodass in Ihren API-Anfragen keine Änderungen oder zusätzlichen Parameter erforderlich sind.

## So funktioniert es

Boosting Groups unterstützen nur positive Priorisierung. Sie können Stationen damit fördern, aber nicht meiden oder ausschließen. Bei alleiniger Verwendung werden geboostete Stationen gegenüber allen anderen Stationen entlang der Route priorisiert.

In Kombination mit Betreiberpräferenzen priorisiert der Routenplaner Stationen in der folgenden Reihenfolge (von der höchsten zur niedrigsten Priorität):

- Aktive Boosting Groups sind einzelne geboostete Stationen. Sie überschreiben alle Betreiberpräferenzen, selbst wenn der Betreiber der Station auf `avoid` oder `excluded` gesetzt ist.
- Bevorzugte Betreiber (`high`, `medium`, `low`) sind Stationen, die zu bevorzugten Ladenetzwerken gehören.
- Nicht eingestufte Stationen sind Standardstationen, für die weder eine Boosting Group noch eine Betreiberpräferenz gilt.
- Herabgestufte Betreiber (`avoid`) sind Stationen von Betreibern, die als zu meiden markiert sind. Sie werden nur verwendet, wenn keine besseren Optionen existieren.

Wie bei Betreiberpräferenzen erfolgt das Boosten von Stationen nach dem Best-Effort-Prinzip. Der Routenplaner wägt die Stationspriorität gegen die Stationsdichte und den Umwegeinfluss ab, sodass die Wahl einer geboosteten Station nie zu einer ineffizienten Route führt.

## Beispiele

<details>
  <summary>Route mit aktiven Boosting Groups berechnen</summary>

  Da Boosting Groups automatisch auf Projektebene angewendet werden, müssen Sie nur eine Standard-Mutation `createRoute` senden. Alle aktiven Boosting Groups werden automatisch priorisiert.

```graphql Example request
mutation CreateRoute {
  createRoute(
    input: {
      vehicle: { id: "607823b2c246f9001b97b1a2" }
      origin: {
        type: Feature
        geometry: { type: Point, coordinates: [4.895168, 52.370216] }
      }
      destination: {
        type: Feature
        geometry: { type: Point, coordinates: [6.773456, 51.227741] }
      }
    }
  ) {
    id
    status
  }
}
```
</details>

<details>
  <summary>Prüfen, ob empfohlene Stationen zu einer Boosting Group gehören</summary>

  Wenn Sie die berechnete Route mit `getRoute` oder der Subscription `route` abrufen, fordern Sie `boosting_group_ids` an der Station des Abschnitts (Leg) an, um zu sehen, welche aktiven Boosting Groups auf diesen Stopp zutrafen.

```graphql Example request {{ mark: [11] }}
query GetRoute {
  getRoute(id: "6527e1f1a8b4c2d3e4f5a6b7") {
    status
    route {
      id
      legs {
        origin {
          properties {
            station_id
            station {
              boosting_group_ids
            }
          }
        }
      }
    }
  }
}
```
</details>
