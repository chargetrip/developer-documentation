# Route erstellen

Migrieren vor: Q1 2027

Migrieren Sie vom veralteten Route-Service auf die neueste Version. Der neue Service bietet ein neu organisiertes Schema, länderspezifische Betreiberpräferenzen, eine schnellere Routenberechnung und bessere Wartbarkeit.

## Operationen

| Alt               | Neu                                                             |
| ----------------- | ----------------------------------------------------------------|
| `newRoute`        | [`createRoute`](/api-reference/light-vehicle/route/mutation-create-route)     |

## Allgemeine Schemaänderungen

- **Explizite Typisierung**: Zuvor flexible JSON-Felder sind jetzt im Schema explizit typisiert, um Struktur und Validierung zu verbessern.
- **Namenskonventionen**: Felder verwenden jetzt `snake_case` statt `camelCase`.
- **Einheitenunterstützung**: Numerische Eingaben unterstützen jetzt verschiedene Einheitentypen, ausgedrückt als Objekt mit `value`, `type` und einer optionalen `source` (`manual`, `telemetry` oder `default`).

## Änderungen an der Mutation

Das Argument `input` von `createRoute` wurde neu organisiert und vereinfacht.

### routeRequest

Auf Root-Ebene wurden die folgenden Felder entfernt. Betreiberbezogene Felder werden jetzt durch [Betreiberpräferenzen](#betreiberpräferenzen) abgedeckt, und ausstattungsbezogene Felder wurden in die eigene [Ausstattungsabfrage](/api-reference/light-vehicle/route/query-get-route-stations-with-amenities) verschoben.

| Feld                   | Verschoben nach                        |
| ---------------------- | -------------------------------------- |
| `operatorIds`          | Entfernt                               |
| `amenities`            | Entfernt                               |
| `amenity_preferences`  | Entfernt                               |
| `operatorRequired`     | Entfernt                               |
| `operatorPrefer`       | Entfernt                               |

### EV

Auf EV-Ebene wurden die meisten Felder der obersten Ebene in ein eigenes `vehicle`-Objekt verschoben.

| Feld              | Verschoben nach                        |
| ----------------- | -------------------------------------- |
| `ev.id`           | `vehicle.id`                     |
| `battery`         | `vehicle`                        |
| `climate`         | `vehicle`                        |
| `heat_pump`       | `vehicle`                        |
| `plugs`           | `vehicle.charging.connectors`    |
| `safeRiskMargin`       | `vehicle.charging.risk_margin`   |
| `chargeMode`           | `vehicle.charging.mode`          |
| `bmsConsumption`  | Entfernt                               |

### Fahrzeugbeladung

Eigenschaften der Fahrzeugbeladung werden nicht mehr an einer einzigen Stelle festgelegt. Sie werden jetzt pro `origin`- und `via`-Punkt angegeben, was eine feinere Steuerung von Insassen- und Ladungsgewicht pro Etappe ermöglicht. Sie befinden sich bei jedem Standort unter `properties.vehicle`, und ihre Feldnamen ändern sich wie folgt:

| Feld        | Verschoben nach       |
| ----------- | --------------------- |
| `occupants` | Unverändert            |
| `cargo`     | `total_cargo_weight`  |

### Telemetrie

Die folgenden Telemetriedaten wurden von der Root-Ebene in das `vehicle`-Objekt verschoben.

| Feld                  | Verschoben nach  |
| --------------------- | ---------------- |
| `heading`             | `vehicle`  |
| `motor_rpm`           | `vehicle`  |
| `odometer`            | `vehicle`  |
| `outside_temperature` | `vehicle`  |
| `tire_pressure`       | `vehicle`  |
| `vehicle_speed`       | `vehicle`  |

## Hervorgehobene Änderungen

Einige Felder des Arguments `input` haben jetzt neue, stärker strukturierte Formen. Sie werden unten ausführlicher behandelt.

### Betreiberpräferenzen

Betreiberpräferenzen wurden auf drei Stufen vereinfacht: `high`, `medium` und `low`. Jeder Eintrag, ob eingestuft, ausgeschlossen oder gemieden, kann über das Feld `countries` auf bestimmte Länder beschränkt werden. Wenn es weggelassen wird, werden alle Länder berücksichtigt.

```graphql Betreiberpräferenzen {{ mark: [6,9,12] }}
input: {
  operators: {
    ranking: {
      type: preferred
      levels: {
        high: [
          {
            id: "op1"
            countries: [NL]
          }
        ]
        low: [
          {
            id: "op3"
          }
        ]
      }
    }
  }
}
```

### Gesamtgewicht der Insassen

Mit einem neuen Feld `total_occupant_weight` können Sie das standardmäßige Insassengewicht überschreiben, ausgedrückt mit dem neuen Einheitenobjekt.

```graphql Gesamtgewicht der Insassen {{ mark: [6,7,8,9,10] }}
input: {
  origin: {
    properties: {
      vehicle: {
        occupants: 3
        total_occupant_weight: {
          value: 160
          type: kilogram
          source: manual
        }
      }
    }
  }
}
```
