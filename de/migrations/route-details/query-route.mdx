# Routendetails

Migrieren bis: Q1 2027

Migrieren Sie vom veralteten Route-Dienst auf die neueste Version. Der neue Dienst bietet ein neu organisiertes Schema, Betreiberpräferenzen pro Land, eine schnellere Routenberechnung und bessere Wartbarkeit.

## Operationen

| Alt                | Neu                                                   |
| ------------------ | ------------------------------------------------------|
| `route`            | [`getRoute`](/api-reference/core/route/query-get-route)     |
| `routeUpdatedById`  | [`route`](/api-reference/core/route/subscription-route)     |

## Allgemeine Schemaänderungen

- **Explizite Typisierung**: Zuvor flexible JSON-Felder sind jetzt im Schema explizit typisiert, um Struktur und Validierung zu verbessern.
- **Namenskonventionen**: Felder verwenden jetzt `snake_case` statt `camelCase`.
- **Einheitenunterstützung**: Numerische Eingaben unterstützen jetzt verschiedene Einheitentypen, ausgedrückt als Objekt mit `value`, `type` und einer optionalen `source` (`manual`, `telemetry` oder `default`).

## Änderungen an Query und Subscription

Benennung und Gruppierung der Felder wurden überarbeitet, und redundante Felder wurden entfernt. Die Antwort enthält jetzt die ursprüngliche Eingabe, angereichert um Standardwerte, sodass sie für künftige Neuberechnungen der Route wiederverwendet werden kann.

### Oberste Ebene

Auf der obersten Ebene werden die meisten Felder unter `recommended` verschoben, und die Eingaben `ev`, `telemetry` und `routeRequest` werden in einem einzigen Objekt `request_input` zusammengefasst.

| Feld           | Verschoben nach        |
| -------------- | ---------------------- |
| `route`        | `recommended`          |
| `alternatives` | Entfernt               |
| `ev`           | `request_input`        |
| `telemetry`    | `request_input`        |
| `routeRequest` | `request_input`        |
| `app`          | `meta.app_id`          |
| `status`       | Unverändert            |

### Route

Auf Routenebene werden die meisten Felder unter `recommended` verschoben und behalten ihre Namen, dazu kommen einige explizite Umbenennungen.

| Feld                  | Verschoben nach                      |
| --------------------- | ------------------------------------ |
| `rangeStart*`         | `range_at_origin`                    |
| `rangeEnd*`           | `range_at_destination`               |
| `charges`             | `recommended.charges`                |
| `distance`            | `recommended.distance`               |
| `consumption`         | `recommended.consumption`            |
| `chargeTime`          | `recommended.durations.charging`     |
| `polyline`            | `recommended.polyline`               |
| `pathPlot`            | `recommended.path_plot`              |
| `legs`                | `recommended.legs`                   |
| `tags`                | `recommended.tags`                   |
| `instructions`        | Entfernt                             |
| `amenityRanking`      | Entfernt                             |
| `stationsAlongRoute`  | `recommended.alternative_stations`   |

### Abschnitte (Legs)

Auf Abschnittsebene folgen die Reichweiten derselben Umbenennung wie bei der Route, und Details zu Insassen und Ladung wandern in die Standorteigenschaften `origin` und `via` jedes Abschnitts.

| Feld          | Verschoben nach                         |
| ------------- | --------------------------------------- |
| `rangeStart*` | `range_at_origin`                       |
| `rangeEnd*`   | `range_at_destination`                  |
| `steps`       | `sections`                              |
| `stationId`   | `recommended.legs.station.station_id`   |

Abschnitte erhalten außerdem ein neues Feld `range_after_charge`.

## Hervorgehobene Änderungen

Die Antwort führt außerdem eine neue, stärker strukturierte Form für Routenabschnitte ein. Sie wird weiter unten ausführlicher beschrieben.

### Sections

Steps wurden durch Sections ersetzt, die detailliertere Informationen liefern, einschließlich Start- und Zieldetails für jede Section.

```graphql Sections {{ mark: [1,13,14,26,27] }}
sections {
  type
  tags
  polyline(decimals: five)
  distance(unit: meter)
  duration
  consumption
  origin {
    id
    type
    properties {
      occupants
      total_occupant_weight
      total_cargo_weight
    }
    geometry {
      type
      coordinates
    }
  }
  destination {
    id
    type
    properties {
      occupants
      total_occupant_weight
      total_cargo_weight
    }
    geometry {
      coordinates
      type
    }
  }
}
```
