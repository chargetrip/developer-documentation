# Routendetails

Migrieren vor: Q1 2027

Migrieren Sie vom veralteten Route-Service auf die neueste Version. Der neue Service bietet ein neu organisiertes Schema, länderspezifische Betreiberpräferenzen, eine schnellere Routenberechnung und bessere Wartbarkeit.

## Operationen

| Alt                | Neu                                                   |
| ------------------ | ------------------------------------------------------|
| `route`            | [`getRoute`](/api-reference/core/route/query-get-route)     |
| `routeUpdatedById`  | [`route`](/api-reference/core/route/subscription-route)     |

## Allgemeine Schemaänderungen

- **Explizite Typisierung**: Zuvor flexible JSON-Felder sind jetzt im Schema explizit typisiert, um Struktur und Validierung zu verbessern.
- **Namenskonventionen**: Felder verwenden jetzt `snake_case` statt `camelCase`.
- **Einheitenunterstützung**: Numerische Eingaben unterstützen jetzt verschiedene Einheitentypen, ausgedrückt als Objekt mit `value`, `type` und einer optionalen `source` (`manual`, `telemetry` oder `default`).

## Änderungen an Abfrage und Subscription

Benennung und Gruppierung der Felder wurden überarbeitet, und redundante Felder wurden entfernt. Die Antwort enthält jetzt die ursprüngliche Eingabe, angereichert um Standardwerte, sodass sie für spätere Routenneuberechnungen wiederverwendet werden kann.

### Oberste Ebene

Auf der obersten Ebene werden die meisten Felder unter `recommended` verschoben, und die Eingaben `ev`, `telemetry` und `routeRequest` werden in einem einzigen Objekt `request_input` zusammengeführt.

| Feld           | Verschoben nach        |
| -------------- | ---------------------- |
| `route`        | `recommended`          |
| `alternatives` | Entfernt               |
| `ev`           | `request_input`        |
| `telemetry`    | `request_input`        |
| `routeRequest` | `request_input`        |
| `app`          | `meta.app_id`          |
| `status`       | Unverändert            |

### Route

Auf Routenebene werden die meisten Felder unter `recommended` verschoben und behalten ihre Namen, zusammen mit einigen expliziten Umbenennungen.

| Feld                  | Verschoben nach                      |
| --------------------- | ------------------------------------ |
| `rangeStart*`         | `range_at_origin`                    |
| `rangeEnd*`           | `range_at_destination`               |
| `charges`             | `recommended.charges`                |
| `distance`            | `recommended.distance`               |
| `consumption`         | `recommended.consumption`            |
| `chargeTime`          | `recommended.durations.charging`     |
| `polyline`            | `recommended.polyline`               |
| `pathPlot`            | `recommended.path_plot`              |
| `legs`                | `recommended.legs`                   |
| `tags`                | `recommended.tags`                   |
| `instructions`        | Entfernt                             |
| `amenityRanking`      | Entfernt                             |
| `stationsAlongRoute`  | `recommended.alternative_stations`   |

### Etappen

Auf Etappenebene folgen die Reichweiten derselben Umbenennung wie bei der Route, und Details zu Insassen und Ladung wandern in die Standorteigenschaften `origin` und `via` jeder Etappe.

| Feld          | Verschoben nach                         |
| ------------- | --------------------------------------- |
| `rangeStart*` | `range_at_origin`                       |
| `rangeEnd*`   | `range_at_destination`                  |
| `steps`       | `sections`                              |
| `stationId`   | `recommended.legs.station.station_id`   |

Etappen erhalten außerdem ein neues Feld `range_after_charge`.

## Hervorgehobene Änderungen

Die Antwort führt außerdem eine neue, stärker strukturierte Form für Routenabschnitte ein. Sie wird unten ausführlicher behandelt.

### Abschnitte

Schritte (`steps`) wurden durch Abschnitte (`sections`) ersetzt, die detailliertere Informationen liefern, einschließlich Start- und Zieldetails für jeden Abschnitt.

```graphql Abschnitte {{ mark: [1,13,14,26,27] }}
sections {
  type
  tags
  polyline(decimals: five)
  distance(unit: meter)
  duration
  consumption
  origin {
    id
    type
    properties {
      occupants
      total_occupant_weight
      total_cargo_weight
    }
    geometry {
      type
      coordinates
    }
  }
  destination {
    id
    type
    properties {
      occupants
      total_occupant_weight
      total_cargo_weight
    }
    geometry {
      coordinates
      type
    }
  }
}
```
