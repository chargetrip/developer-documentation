Mit Filtern können Anwendungen die Ladestationen eingrenzen, die von der Tile Service API zurückgegeben werden. Neben dem reinen Ausblenden nicht passender Ergebnisse transformieren bestimmte Filter auch die Stationsdaten, damit die Antwort kontextuell relevant ist.

## Wie Filter die Daten beeinflussen

Wenn eine Anfrage Filter enthält, führt der Tile Service zwei unterschiedliche Operationen aus:

1. **Ausschluss nicht passender Stationen**
   Jede Station, die die angegebenen Filterkriterien nicht erfüllt, wird vollständig aus der Antwort entfernt. Diese Operation erfolgt, wenn Filter auf Stationsebene oder auf EVSE-Ebene verwendet werden.
2. **Datentransformation**
   Wenn bestimmte Filterparameter angegeben werden, berechnet der Tile Service einige dynamische Eigenschaften der Station neu. Diese Operation erfolgt, wenn Filter auf EVSE-Ebene verwendet werden.

## Implementierung

Filterparameter können als Query-Strings an die Anfrage-URL jedes Tile-Service-Endpoints (MVT, JSON oder Count) angehängt werden. Wenn keine Filter angewendet werden, werden alle verfügbaren Ladestationen zurückgegeben, und es erfolgen keine Datentransformationen.

```bash Tile / Filter / Example
https://api.chargetrip.io/v2/station/..../?{filter_1}&{filter_2}&{filter_n}
```

## Ebenen

Filter können auf zwei Ebenen existieren: auf EVSE-Ebene oder auf Stationsebene, jeweils mit eigenen Auswirkungen und Ergebnissen, wie unten beschrieben.

### Stationsebene

Filter, die die globalen Attribute der Station auswerten. Diese Filter schließen nur aus: Sie schließen nicht passende Stationen aus, verändern aber nie die zurückgegebenen Datenfelder.

`amenities` · `enum` · [Beispiel-URL anzeigen](tip:https://api.chargetrip.io/v2/station?amenities[]=HOTEL)
: Filtert so, dass nur Stationen enthalten sind, die die angegebenen Ausstattungen bieten.
: `HOTEL`, `SHOPPING`, `BATHROOM`, `SUPERMARKET`, `PLAYGROUND`, `PHARMACY`, `MUSEUM`, `COFFEE`, `RESTAURANT`

`preferred_operators` · `boolean` · [Beispiel-URL anzeigen](tip:https://api.chargetrip.io/v2/station?preferred_operators=true)
: Filtert so, dass nur Stationen enthalten sind, die von Betreibern betrieben werden, die als bevorzugt konfiguriert sind. Bevorzugte Betreiber können in den Projekteinstellungen im Dashboard festgelegt werden.
: `true`, `false`

`truck_dedicated` · `boolean` · [Beispiel-URL anzeigen](tip:https://api.chargetrip.io/v2/station?truck_dedicated=true)
: Filtert so, dass nur Stationen enthalten sind, die speziell oder hauptsächlich zum Laden von Lkw vorgesehen sind. **Nur anwendbar, wenn die Eco-Movement-Stationsdatenbank verwendet wird, andernfalls wird er ignoriert.**
: `true`, `false`

### EVSE-Ebene

Filter, die die spezifischen Ladefähigkeiten der Station auswerten. Diese Filter schließen aus und führen eine [Transformation](/api-reference/tiles/filters#beispiele-für-datentransformation) durch: Nicht passende Stationen werden ausgeschlossen, und bei passenden Stationen werden die dynamischen Felder neu berechnet.

`connectors` · `enum` · [Beispiel-URL anzeigen](tip:https://api.chargetrip.io/v2/station?connectors[]=CHADEMO)
: Filtert so, dass nur Stationen enthalten sind, die EVSEs mit den angegebenen Anschlusstypen haben. Akzeptiert ein Array von Strings mit beliebigen OCPI-2.2.1-Anschlusswerten.
: `CHADEMO`, `DOMESTIC_A`, `DOMESTIC_B`, `DOMESTIC_C`, `DOMESTIC_D`, `DOMESTIC_E`, `DOMESTIC_F`, `DOMESTIC_G`, `DOMESTIC_H`, `DOMESTIC_I`, `DOMESTIC_J`, `DOMESTIC_K`,
`DOMESTIC_L`, `DOMESTIC_M`, `DOMESTIC_N`, `DOMESTIC_O`, `IEC_60309_2_single_16`, `IEC_60309_2_three_16`, `IEC_60309_2_three_32`, `IEC_60309_2_three_64`, `IEC_62196_T1`,
`IEC_62196_T1_COMBO`, `IEC_62196_T2`, `IEC_62196_T2_COMBO`, `IEC_62196_T3A`, `IEC_62196_T3C`, `PANTOGRAPH_BOTTOM_UP`, `PANTOGRAPH_TOP_DOWN`, `TESLA_R`, `TESLA_S`, `GB_T`,
`CHAOJI`, `NEMA_5_20`, `NEMA_6_30`, `NEMA_6_50`, `NEMA_10_30`, `NEMA_10_50`, `NEMA_14_30`, `NEMA_14_50`

### Beispiele für Datentransformation

Einige Ausgaben werden neu berechnet, wenn Filter auf EVSE-Ebene angewendet werden. Diese Felder werden „transformiert“, damit Anschlüsse ignoriert werden, die nicht den Suchkriterien des Nutzers entsprechen.
Diese „dynamischen“ Ausgabefelder sind `connector_maximum_power` und `evse_status_*`.

<details>
  <summary>Gleicher Filtertyp, unterschiedliche Werte</summary>
  Die Anfrage enthält einen CHADEMO-Anschlussfilter. Die Station ist enthalten, weil sie einen CHADEMO-Anschluss hat, aber die dynamischen Felder werden so transformiert, dass die Combo-Typ-1-Lader ignoriert werden.

```bash Example URL
https://api.chargetrip.io/v2/station?connectors[]=IEC_62196_T1_COMBO&connectors[]=CHADEMO
```

```json Response
{
  "id": "station_a",
  // Static: Remains 150 kW (This represents the station maximum power across all connectors)
  "station_maximum_power": 150,
  // Dynamic: Adjusted to 100 kW (Max power of the CHADEMO connector)
  "connector_maximum_power": 100,
  // Dynamic: Counts the 1 CHADEMO chargers
  "evse_status_out_of_order": 0,
  // Dynamic: 0, because the charging Type 1 plugs are filtered out
  "evse_status_available": 1
}
```
</details>
