Um Antwortzeit und -größe zu optimieren, geben die MVT- und die JSON-API standardmäßig eine minimierte Antwort zurück. Dieser Ansatz sorgt für maximale Performance und reduziert die Größe der Kachel-Payloads, was für flüssige Karteninteraktionen entscheidend ist. Mit Selektoren können Sie die zusätzlichen Datenpunkte einbeziehen, die Ihre Anwendung konkret benötigt.

## Verfügbare Selektoren

Jedes Feld, das in den Stationseigenschaften für MVT- und JSON-Kacheln aufgeführt ist, kann im jeweiligen Service als Selektor verwendet werden, mit Ausnahme der obligatorischen GeoJSON-Felder, die der JSON-Endpoint zurückgibt.

`count` · `integer` · <span class="text-accent">default</span>
: Die Anzahl der Stationen innerhalb eines Clusters. Eine Anzahl von 1 bedeutet ein Stations-Feature, eine Anzahl größer als 1 ein Cluster-Feature.

`expansion_zoom` · `integer` · <span class="text-accent">default</span>
: Die Zoomstufe, bei der sich ein Cluster in mehrere kleinere Cluster oder Stationen aufteilt.

`id` · `string`
: Die Kennung der Station.

`lng` · `float`
: Der Längengrad der Station.

`lat` · `float`
: Der Breitengrad der Station.

`station_maximum_power` · `integer`
: Die maximale Ladeleistung (in kW), die an der Station verfügbar ist. Dieser Wert ist statisch und spiegelt unabhängig von Anschlussfiltern immer die höchste Leistungsfähigkeit der Station wider.

`connector_maximum_power` · `integer`
: Die maximale Ladeleistung (in kW), die von den Anschlüssen verfügbar ist, die dem Filter `connectors[]` entsprechen. Wenn kein Filter angegeben ist, werden alle Anschlüsse berücksichtigt, und der Wert entspricht `station_maximum_power`.

`preferred_operator` · `boolean`
: Gibt an, ob der Betreiber einer Station ein bevorzugter Betreiber ist. Bevorzugte Betreiber können auf Projektebene im Dashboard verwaltet werden.

`evse_status_blocked` · `integer`
: Die Anzahl der EVSEs im Status „blocked“. Wenn ein Filter `connectors[]` angegeben ist, werden nur blockierte EVSEs gezählt, die den ausgewählten Anschlusstypen entsprechen.

`evse_status_planned` · `integer`
: Anzahl der EVSEs im Status „planned“. Wenn ein Filter `connectors[]` angegeben ist, werden nur geplante EVSEs gezählt, die mindestens einen der ausgewählten Anschlusstypen haben.

`evse_status_available` · `integer`
: Anzahl der EVSEs im Status „available“. Wenn ein Filter `connectors[]` angegeben ist, werden nur verfügbare EVSEs gezählt, die mindestens einen der ausgewählten Anschlusstypen haben.

`evse_status_charging` · `integer`
: Anzahl der EVSEs im Status „charging“. Wenn ein Filter `connectors[]` angegeben ist, werden nur ladende EVSEs gezählt, die mindestens einen der ausgewählten Anschlusstypen haben.

`evse_status_unknown` · `integer`
: Anzahl der EVSEs im Status „unknown“. Wenn ein Filter `connectors[]` angegeben ist, werden nur EVSEs mit unbekanntem Status gezählt, die mindestens einen der ausgewählten Anschlusstypen haben.

`evse_status_reserved` · `integer`
: Anzahl der EVSEs im Status „reserved“. Wenn ein Filter `connectors[]` angegeben ist, werden nur reservierte EVSEs gezählt, die mindestens einen der ausgewählten Anschlusstypen haben.

`evse_status_out_of_order` · `integer`
: Anzahl der EVSEs im Status „out_of_order“. Wenn ein Filter `connectors[]` angegeben ist, werden nur außer Betrieb befindliche EVSEs gezählt, die mindestens einen der ausgewählten Anschlusstypen haben.

`evse_status_inoperative` · `integer`
: Anzahl der EVSEs im Status „inoperative“. Wenn ein Filter `connectors[]` angegeben ist, werden nur nicht betriebsbereite EVSEs gezählt, die mindestens einen der ausgewählten Anschlusstypen haben.

## Implementierung

Um bestimmte Eigenschaften anzufordern, hängen Sie den Query-Parameter `station_properties[]` an die URL der Kachelanfrage an.

```bash Tile / Selectors / Example
https://api.chargetrip.io/v2/station/.../?station_properties[]={selector1}&station_properties[]={selector2}&station_properties[]={selector3}
```

## Verhaltensbeispiele

Wenn Selektoren angegeben werden, gibt die Anfrage nur die angegebenen Felder zurück.

### GeoJSON

Im GeoJSON-Endpoint werden die obligatorischen GeoJSON-Felder (`type`, `geometry` und `id`) unabhängig von den gewählten Selektoren immer zurückgegeben.

```json JSON Selectors example
{
  "type": "FeatureCollection",
  "features": [
    // Station feature
    {
      "id": "132313",
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [6.789, 52.234]
      },
      // 'count' is missing because it wasn't provided as selector
      "properties": {
        "station_maximum_power": 350,
        "preferred_operator": true
      }
    },
    // Cluster feature
    // Cluster feature is not modified, as it's not affected by the selectors.
    {
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [6.723, 50.0]
      },
      "properties": {
        "count": 3,
        "expansion_zoom": 18
      }
    }
  ]
}
```

### MVT

Im MVT-Endpoint werden nur die ausdrücklich ausgewählten Parameter zurückgegeben, da es keine obligatorischen Felder gibt.

```json MVT Selectors example
// Station feature
// 'count' is missing because it wasn't provided as a selector.
{
  "id": "132313",
  "preferred_operator": false,
  "station_maximum_power": 350
}

// Cluster feature
// Cluster feature is not modified, as it's not affected by the selectors.
{
  "count": 3,
  "expansion_zoom": 32
}
```
