Chargetrip führt bedeutende neue Funktionen über ein strukturiertes Experimentalprogramm ein. Es gibt Ihnen frühen Zugriff, um kommende Funktionen zu evaluieren und deren Design zu beeinflussen, bevor Schemas und Verträge dauerhaft werden.

> [!WARNING] Ausnahme von der 12-monatigen Verwerfungsrichtlinie
> Funktionen in Alpha und Beta sind von der [12-monatigen Verwerfungsrichtlinie](/api-reference/api/lifecycle#verwerfungszeitplan) ausgenommen und können sich ändern oder früher eingestellt werden.

## Arten experimenteller Funktionen

- Neue Operationen: Völlig neue Queries, Mutationen oder Subscriptions.
- Erweiterungen bestehender Operationen: Neue optionale Argumente oder Ausgabefelder, die zu bestehenden stabilen Operationen hinzugefügt werden.

## Phasen experimenteller Funktionen

| Dimension | Alpha | Beta |
 | ----- | ----- | ----- |
| **Produktionsreife** | Für Produktionsumgebungen ausdrücklich nicht empfohlen. | Geeignet für kontrollierte Pilotprojekte. Nicht empfohlen für geschäftskritische Abläufe. |
| **Aktivierung** | Standardmäßig deaktiviert. Erfordert ein explizites Opt-in im Dashboard. | Standardmäßig für alle Clients aktiviert. |
| **Stabilität** | Stabil, aber häufigen Schemaänderungen unterworfen.| Stabil. Kann kleinere Schemaänderungen enthalten. |
| **Schema-Kennzeichnung** | In den Schema-Feldbeschreibungen mit `[ALPHA]` gekennzeichnet. | In den Schema-Feldbeschreibungen mit `[BETA]` gekennzeichnet. |
| **Einstellungsmitteilung** | Keine. Kann jederzeit sofort geändert oder eingestellt werden. | Proaktive, direkte Kontaktaufnahme mit Kunden, die aktiv integrieren. |

Informationen darüber, was stabile Funktionen garantieren, finden Sie unter [API-Lebenszyklus](/api-reference/api/lifecycle).


## Bewährte Vorgehensweisen

 - Verwenden Sie Alpha-Funktionen für Sandbox-Evaluierungen, Proofs of Concept und Feedback. Wenn Sie eine trotzdem produktiv einsetzen, erhalten Sie bei Änderungen weder eine Benachrichtigung noch Kompatibilitätsschutz.
 - Wenn Sie Beta-Funktionen für Endnutzer bereitstellen, zeigen Sie ein „Beta“-Badge an, damit diese wissen, dass sich die Funktion noch stabilisiert.


## Graduierungs-Lebenszyklus

1. **Alpha zu Beta** Wenn Funktionalität und Schema eine ausreichende Reife erreichen, wird die Funktion zu Beta graduiert. Das Beschreibungs-Tag wechselt von `[ALPHA]` zu `[BETA]`, der Zugriff wird für alle Kunden standardmäßig aktiviert, und die Änderungen werden in den Release Notes angekündigt.

2. **Beta zu Stabil** Wenn Zuverlässigkeit und Reife bei mehreren Clients bestätigt wurden, werden das Beschreibungs-Tag `[BETA]` und die Laufzeitwarnungen entfernt, und die Funktion wechselt in den [stabilen Lebenszyklus](/api-reference/api/lifecycle).


## Preise
- Anfragen an Operationen, die als experimentell gekennzeichnet sind, sind **kostenlos**.
- Anfragen an stabile Endpoints, die optionale experimentelle Eingabeargumente oder Ausgabefelder enthalten, werden gemäß Ihrem Abonnementplan **berechnet**.

## Programmatische Warnungen
Damit Ihr Entwicklungsteam experimentelle Abhängigkeiten im laufenden Datenverkehr im Blick behält, geben API-Antworten, die Alpha- oder Beta-Funktionen nutzen, Warnungsmetadaten im GraphQL-`extensions`-Block zurück:

```json Example request and response

  "data": {
    "getTruckRoute": {
      "id": "dd07b4d0-6b79-11f0-bf8f-e6b813282ac3",
      "status": "done"
    }
  },
  "extensions": {
    "warnings": [
      {
        "code": "ALPHA_FEATURE",
        "path": ["getTruckRoute"],
        "message": "This feature is currently in ALPHA. Visit https://developers.chargetrip.com/api-reference for more information."
      }
    ]
  }
}
```
</details>
