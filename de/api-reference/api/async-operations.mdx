---
title: Asynchrone Operationen
---

Einige Operationen, etwa das Erstellen einer Route oder einer zugeordneten Route, laufen asynchron ab, damit die API reaktionsfähig bleibt. Anstatt darauf zu warten, dass eine Mutation das vollständige Ergebnis zurückgibt, erhalten Sie sofort eine `id` und verfolgen und rufen das Ergebnis anschließend damit ab.

## So funktioniert es

1. **Erstellen**
   Rufen Sie die Mutation auf. Sie gibt sofort eine `id` zurück, die Sie im nächsten Schritt verwenden, um das Ergebnis zu verfolgen und abzurufen.
2. **Subscription öffnen**
   Abonnieren Sie mit der `id` aus dem vorherigen Schritt. Während das Ergebnis berechnet wird, sendet die Subscription Status-Updates, mit denen Sie einen asynchronen Ladezustand in Ihrer UI steuern können.
3. **Ergebnis darstellen**
   Sobald `status` einen finalen Wert erreicht, stellen Sie die passende UI für dieses Ergebnis dar.
4. **Fertiges Ergebnis erneut abrufen**
   Sobald ein Ergebnis einen finalen Status erreicht hat, ist es bereits vorberechnet. Wenn Sie es später erneut benötigen, zum Beispiel nach dem Zurücknavigieren, verwenden Sie die passende Query, anstatt eine neue Subscription zu öffnen.

## Wo dies gilt

| Funktion | Mutation | Subscription | Query |
| --- | --- | --- | --- |
| [Route](/docs/getting-started/route) | `createRoute` | `route` | `getRoute` |
| [Zugeordnete Route](/api-reference/matched-route/mutation-create-matched-route) | `createMatchedRoute` | `matchedRoute` | `getMatchedRoute` |
| [Isoline](/api-reference/isoline/mutation-create-isoline) | `createIsoline` | `isoline` | `isoline` |
| [Lkw-Route](/api-reference/truck-route/mutation-create-truck-route) | `createTruckRoute` | `truckRoute` | `getTruckRoute` |
| [Navigation](/api-reference/navigation/mutation-start-navigation) | `startNavigation` | `navigation` | `navigation` |
