---
title: "Pagination"
description: "Blättern Sie mit cursorbasierter und offsetbasierter Pagination durch Listen-Queries, einschließlich der Limits, die für jede Seite gelten."
---

Damit die API schnell und reaktionsfähig bleibt, begrenzen Listen-Queries, wie viele Daten in einer einzelnen Anfrage zurückgegeben werden. In der API werden zwei Pagination-Arten verwendet:

- Cursorbasiert (aktuell): wird von neu entwickelten Listen-Queries verwendet.
- Offsetbasiert (Legacy): wird von den meisten bestehenden Listen-Queries verwendet. Diese werden irgendwann durch cursorbasierte Versionen ersetzt.

> [!WARNING] Pagination-Limits
> Unabhängig von der Pagination-Art geben Listen-Queries höchstens 100 Elemente pro Seite zurück. Ausgenommen ist die Query `getRouteStationsWithAmenities`, die auf 10 begrenzt ist.

## Cursorbasierte Pagination

Die cursorbasierte Pagination ist der aktuelle Standard. Mit ihr legen Sie den Startpunkt einer Anfrage über einen Cursor fest, eine eindeutige Kennung für eine Position in der Ergebnismenge.

### Argumente

`first` · <span class="text-muted">Integer</span>
: Die Anzahl der zurückzugebenden Elemente.

`after` · <span class="text-muted">String</span>
: Der Cursor, ab dem begonnen wird. Lassen Sie dieses Argument weg oder setzen Sie es auf `null`, um die erste Seite abzurufen. Verwenden Sie für weitere Seiten den Wert `page_info.end_cursor` aus der vorherigen Antwort.

### Antwort

Die Antwort liefert die Ergebnisse direkt über ein `nodes`-Array, zusammen mit Pagination-Metadaten.

`nodes` · <span class="text-muted">Array</span>
: Die Liste der Datenobjekte für die aktuelle Seite.

`total_count` · <span class="text-muted">Integer</span>
: Die Gesamtzahl der Elemente, die der Query entsprechen, über alle Seiten hinweg.

`page_info.has_next_page` · <span class="text-muted">Boolean</span>
: Ob nach der aktuellen Seite weitere Ergebnisse verfügbar sind.

`page_info.has_previous_page` · <span class="text-muted">Boolean</span>
: Ob vor der aktuellen Seite weitere Ergebnisse verfügbar sind.

`page_info.start_cursor` · <span class="text-muted">String</span>
: Der Cursor des ersten Knotens in `nodes`.

`page_info.end_cursor` · <span class="text-muted">String</span>
: Der Cursor des letzten Knotens in `nodes`. Verwenden Sie diesen Wert als `after`-Argument in Ihrer nächsten Query.

## Offsetbasierte Pagination (Legacy)

Die offsetbasierte Pagination ist der Legacy-Standard und wird noch von den meisten Listen-Queries verwendet. Sie nutzt `page`, um eine bestimmte Anzahl von Datensätzen zu überspringen, und `size`, um ein Ergebnisfenster fester Größe zurückzugeben.

### Argumente

`size` · <span class="text-muted">Integer</span>
: Die Anzahl der zurückzugebenden Elemente pro Seite.

`page` · <span class="text-muted">Integer</span>
: Die abzurufende Seitennummer. Lassen Sie dieses Argument weg oder setzen Sie es auf `0`, um die erste Seite abzurufen.

### Antwort

Die Antwort liefert direkt eine Liste von Datenobjekten, begrenzt durch den Wert von `size`.
